# A9PJ M1.8 BG1 keyboard asset provenance slice（2026-08-16）

本切片只保存可審核的執行期 metadata、hash、PC/LR、寄存器摘要與 bounded
protocol receipt。ROM、RAM／VRAM raw、圖片與 mGBA 暫存 build 都留在
`/private/tmp`；本切片沒有建立 source table、work ledger 或翻譯 row。

## 範圍與工具

- ROM identity：`A9PJ`／`TOW SUMMLINE`／`AF`／8 MiB；SHA-256
  `b41c293fc0ed6111b7a37d960d9cd0c685e5d521a4739e0e2eaa7ff6186cfdd3`。
- 本 session 暫存 mGBA：`127.0.0.1:39123`；只使用本 session 啟動與停止的
  process。
- 工具：`tools/m18_bg1_asset_probe.py`；GDB transport、standard capture 與
  rendering 仍重用 `core/gba`。遊戲工具只補 A9PJ 的 BG1／DMA 位址、keyboard gate、
  hash 與 bounded stop metadata。
- watch 範圍：從 initial GDB stop 開始，`BG1CNT=0x0400000A`、
  `0x06004020`／`0x06004040` 兩個 32-byte tile、DMA0–3 control register；每次
  transition 最多兩個 `START`，DMA rearm 有上限。

參考 receipt 留在研究者本機：
`/private/tmp/tow-a9pj-m18-runtime-15/summary.json`。該次有完整 reset window、
兩個 START 的 bounded input loop 與 standard capture 嘗試；最後 capture 遇到
暫存 mGBA 的 queued `S02`，因此 termination 是
`bounded-trace-complete-core-capture-limited`。後續用更嚴格的 stale-packet filter
重跑時，listener／GDB 啟動本身也有 bounded failure；不把那些 failure 當成遊戲
路徑命中。

## 已取得的 reset-stage 實證

### BG1 register 與 BIOS tile copy

BG1CNT write watch 命中一次：

| 欄位 | receipt |
| --- | --- |
| stop | `T05watch:0400000A;` |
| writer PC／LR | `0x080141FA`／`0x080141F3` |
| value | `0x0105` |
| decode | 4bpp、charbase `0x4000`、screenbase `0x0800` |

這個 register 值和 M1.6/M1.7 的 keyboard BG1 設定相同，但它只證明 register
設定，不證明此刻畫面已經是 keyboard。

`0x06004020` tile write 另命中一次：

| 欄位 | receipt |
| --- | --- |
| stop | `T05watch:06004020;` |
| writer PC／LR | `0x00000008`／`0x0806C2E6` |
| writer class | BIOS copy candidate |
| tile hash at stop／after step | `02d449a31fbb267c8f352e9968a79e3e5fc95c1bbeaa502fd6454ebde5a4bedc` |
| M1.6 keyboard tile-1 hash | `b5ae44407e13c9f6c085af00c74f47811dff6afe93020f068bdc33b8c1ff39c2` |

hash 不同，所以這不是已知鍵盤第一格的 glyph identity。`0x06004040` 在這個
reset window 沒有 write hit。這是一條「BIOS 在 reset-stage 寫入同一 charblock
位置」的實證，不是 font-record 或 keyboard asset source 的實證；BIOS copy 的
source pointer 只保留 live register candidates/hash，沒有任意把寄存器值當成 source
buffer。

### DMA control receipt

本次共有 5 個 control stop：DMA3 writer PCs
`0x08000558`、`0x0800056A`、`0x08000586`，以及 DMA1／DMA2 writer PCs
`0x0806B496`／`0x0806B4A4`。DMA0 沒有 hit。這些命中可證明「哪些 CPU 指令寫過
DMA control」，但該次 GDB queue 已出現跨 command 的 register／memory payload；
source/destination 欄位出現未對齊或不屬於 GBA 可讀區的值，不能當成有效 DMA
source、destination 或 length。

因此本切片只保留以下陰性界線：沒有取得一筆**可信且 byte-level 可驗證**的 DMA
copy 到 `0x06004000` slice；不能把污染後的 `target_overlap=false` 當成 DMA 已被
排除。CPU、DMA、BIOS 已分開標記，但 DMA source→destination 因 protocol boundary
仍是 unknown。

## Keyboard gate 與 identity gate

參考 receipt 的兩次 START 後，BG1 selected positions 全為 entry `0x0000`，
tile IDs 為 0/8，position match count 為 0；因此 `keyboard_gate=false`。這次沒有
在 keyboard transition 上取得有效 tilemap／rendered grid 三方交叉，不能宣稱已捕獲
keyboard initialization。

目前 M1.8 identity 狀態：

| 對象 | 狀態 | 原因 |
| --- | --- | --- |
| reset-stage `0x06004020` tile | unknown／非 keyboard candidate | BIOS write 命中，但 hash 不等於 keyboard tile-1，且未有五十音位置 gate |
| keyboard tile-1／tile-2 | unknown | keyboard gate 未通過；tile-2 無有效 write hit |
| code unit→BG1 tile | 未建立 | 沒有 font record/source byte-identical 或明確 transform chain |
| confirmed glyph identity | `0` | 沒有同時滿足 table arithmetic、runtime tile hash、keyboard position |

## 與 M1.7 font-record path 的比較

M1.7 已證實 `0x005E`／`0x0066` 由 reader caller LR `0x080063C7` 進入
`0x08089E00 + code_unit*0x18` font-record path，並由 CPU renderer 寫到
`0x060020xx`／`0x060023xx`，不是 BG1 `0x060040xx`。

本 M1.8 的唯一 BG1 tile hit 是 BIOS PC `0x00000008`、LR `0x0806C2E6`，沒有
`0x080063C7` shared LR，也沒有同一 caller／record pointer 的 runtime receipt。
截至這個 bounded boundary，兩者應記為「未連接的兩條 renderer candidate」，不能
合併 codepage；因 keyboard gate 失敗，這還不是對 keyboard transition caller 的
最終排他證明。

## Protocol-limited negative evidence

暫存 mGBA GDB stub 在 watch stop 後曾把 `T05watch`、`S05`、`S02`、`OK` 或上一筆
memory/register payload 延遲到下一個 command。M1.8 probe 已把這些 response filter
限定在遊戲專用工具內：register/memory/Z/z/continue/step/write 都有固定重試上限，
非 data／stop 回應不會被當成 writer 或 source。參考 receipt 仍留下 48 筆
unexpected stale stops；這些被視為 protocol negative，不作遊戲語意證據。

## 下一個最小缺口

先以新 mGBA process 重現已知 `START` keyboard gate，再把高頻 DMA control watch
拆成單通道、單次且在 gate 前後分段；同時保留 `0x06004000` slice watch。只有取得
可信 source/destination（或 CPU copy source）、實際 BG1 tile bytes/hash 與五十音
位置三方一致後，才可提升 glyph identity；之後才有資格開始控制碼或 source-table
工作。M1.8 不等於翻譯完成。
