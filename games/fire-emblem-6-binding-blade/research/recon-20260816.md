# AFEJ 唯讀偵察紀錄（2026-08-16）

## 邊界與當前結論

本紀錄只涉及 `games/fire-emblem-6-binding-blade/`。執行偵察時，工作樹沒有 `roms/base/AFEJ.gba`，也沒有其他可辨識的 FE6 ROM；因此沒有本機 CRC、雜湊或 ROM 內容證據。所有「未確認」項目保持未確認，不以公開 patch、完整解包或搜尋摘要替代。

候選資料代碼 `AFEJ` 只代表預期的 GBA game code。實際身分必須由 ROM 標頭 `0xAC..0xAF`、標頭補數與本機雜湊共同確認。

## 專案內可重跑入口

```sh
python3 tools/recon_afej.py roms/base/AFEJ.gba --json-out work/afej-recon.json
```

該工具是結構掃描器，不是解碼器。它會：

- 解析 GBA 標頭並計算 CRC32、MD5、SHA-1、SHA-256。
- 搜尋少量標準 Shift-JIS UI 探針；零命中只能排除「直接存放這些探針」，不能證明沒有文本。
- 掃描 ROM 位址型 32-bit little-endian 值，列出連續指標候選；未經反組譯／執行期交叉驗證不得稱為字串表。
- 掃描 BIOS LZ77／Huffman／RLE 等標頭候選；標頭命中不是壓縮資料被文本使用的證據。
- 以 4bpp tile 窗口產生字形候選；必須再用畫面、VRAM、實際重複字形與 ROM 原 bytes 比對確認。

輸出報告放在 `work/`；它不應包含解出的日文原文。若後續解碼器產生原文表，檔名必須採 `research/afej-decoded.jsonl`，由 `.gitignore` 保護，不能加入 Git。

## 公開參考資料（不是本專案原文來源）

1. [FEBuilderGBA 原始碼](https://github.com/FEBuilderGBA/FEBuilderGBA)：README 明確列出 FE6 支援。它適合用來辨認 FE6 的資料類型與工具入口，但不能取代本機日版 ROM。
2. [FireEmblemUniverse/fireemblem6j](https://github.com/FireEmblemUniverse/fireemblem6j)：日版 FE6 反編譯工程；其 README 要求使用者自行提供 `fe6-base.gba`，並列出一個可重建 ROM 的外部 SHA-1 `a57095da867de4d585c33d4394712986245fe6ca`。該值不是本機 AFEJ 身分證據，待 ROM 到位後只作比對線索。
3. [FEBuilderGBA 社群說明](https://feuniverse.us/t/fe-builder-gba-if-you-have-any-questions-attach-report7z/2845?page=194)：說明既有 FE6 英譯使用 `.tbl` 把拉丁字母映射到日版字串，並提醒新增字元需要字型。這支持「既有英譯不可直接當日版碼頁／原文」的安全邊界，不採用其翻譯文本。

## 外部工程提供的偵察分區線索

`fireemblem6j` 的公開目錄把文本相關材料分成 `texts/events`、`texts/gamedata`、`texts/misc`、`texts/talks`、`texts/textdefs.txt` 與 `texts/texts.txt`；其 `data/` 另有 `text` 及 `systemlabels_data.h`。這些名稱足以安排本地 ROM 到位後的抽取覆蓋矩陣：劇情／事件、支援、資料表、系統標籤與圖像／介面文字分開驗證；它們不是本機 AFEJ 的地址或內容證明。

FEBuilder 的公開設定說明提到 `translate_textid`、TEXT table extension 與 Text Export。這表示 FEBuilder 的 Text ID／匯出層可作為對照工具，但不能先假定其 ID、表格邊界、碼頁或擴展行為就是日版原 ROM 的原生格式。M1 仍須以 AFEJ 的真實引用者、字串終止、字型讀取和未修改 round-trip 重新證明。

參考：[FE6 `texts/` 目錄](https://github.com/FireEmblemUniverse/fireemblem6j/tree/main/texts)、[FE6 `data/` 目錄](https://github.com/FireEmblemUniverse/fireemblem6j/tree/main/data)、[FEBuilder 設定資料結構說明](https://laqieer.github.io/dw.ngmansion.xyz/wiki/en/guide/febuildergba/the_config_data_structure_of_febuildergba_en.html)。

| 圖像文字與字型 | unknown | 4bpp／tilemap／OBJ 位置、VRAM 複製、重複字形 byte match |

| 回插 | blocked | 先完成嚴格 extractor，再以未修改 ROM round-trip 證明；禁止先套 FEBuilder 或既有 patch |

## 偵察原則

- 不把 FE6 套用黃金太陽的 Huffman、共用碼頁或 `{HH}` 控制碼假設。
- 「字形資料位置已找到」與「每個字形身分已確認」分開記錄；OCR 只能是候選證據。
- 任何使用既有英譯的資料只可作介面／欄位線索，不能作原文、專名或翻譯來源。
- 任何日文腳本、OCR 輸出、渲染圖與 ROM 讀值只留在本機 `research/`／`work/` 被忽略路徑；提交的研究筆記只保存方法、範圍、hash、offset 與短小消歧所需資訊。
