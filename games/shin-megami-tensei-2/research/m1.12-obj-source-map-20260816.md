# M1.12 OBJ destination source-class mapping（2026-08-16）

## 範圍與工具

M1.11 已確認 12 個 `0x06010000` literal-load PCs。本回合先用
`tools/m112_obj_source_map.py` 對每個 PC 周圍的 Thumb DMA3 field sequence 做
bounded decode，再以 `tools/m112_obj_runtime.py` 準備自然 transition runtime
trace。沒有全 ROM glyph scan、沒有 RAM/VRAM dump、沒有 selector/state write，
也沒有建立 source table 或翻譯 ledger。

靜態重現命令：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -B \
  games/shin-megami-tensei-2/tools/m112_obj_source_map.py \
  --rom /private/tmp/smt2-a5tj.gba \
  --output /private/tmp/smt2-m112-static-source.json
```

ROM SHA-256 仍為
`819a6a19a40bfbe7608f4b813dc18285c827f64e1523561ffe8e10ce8ab5991e`；報告
schema 為 `smt2.m1.12.obj-source-map.v1`，只輸出 address、source class、
control／length、caller address、window／sample hash 與 count。

## Confirmed：7 個 bounded DMA3 source edges

decoder 不要求每個 block 都有獨立 prologue 或立即 `BX LR`，但要求：

1. bounded window 內有載入 `0x040000d4` 的 DMA3 register；
2. source literal 後有 SAD store、`0x06010000` destination literal 後有 DAD
   store；
3. control literal 後有 CNT store與 CNT read；
4. register/field offset 交叉一致。

12 個 reference 中有 7 個符合，source address 分布為
`0x02001000 × 2`、`0x02006000 × 1`、`0x0200f874 × 2`、`0x081b13b8 × 2`：

| destination literal PC | pattern entry | source | control | units | source class |
| --- | --- | --- | --- | ---: | --- |
| `0x080bd136` | `0x080bd130` | `0x02001000` | `0x84001000` | `0x1000` | EWRAM runtime／staging candidate |
| `0x080c1350` | `0x080c132e` | `0x081b13b8` | `0x84000800` | `0x800` | ROM data-pointer candidate |
| `0x080d1dfc` | `0x080d1df6` | `0x081b13b8` | `0x84000800` | `0x800` | ROM data-pointer candidate |
| `0x080d5e6e` | `0x080d5e68` | `0x0200f874` | `0x84002000` | `0x2000` | EWRAM runtime／staging candidate |
| `0x080d9a3e` | `0x080d9a38` | `0x02006000` | `0x84000800` | `0x800` | EWRAM runtime／staging candidate |
| `0x080dc6aa` | `0x080dc6a4` | `0x0200f874` | `0x84001400` | `0x1400` | EWRAM runtime／staging candidate |
| `0x0813efce` | `0x0813efc8` | `0x02001000` | `0x84002000` | `0x2000` | EWRAM runtime／staging candidate |

其中 `0x02001000 → 0x06010000` 的兩條 edge 是新的 static fact，特別是
`0x0813efce` 的 `0x84002000` transfer；它們仍沒有證明 `0x02001000` 內容
是文字。`0x0200f874` 曾在 M1.6 被記為 generic LZ77/resource destination
path；本回合只把它分類為 EWRAM runtime source，不回推其資料語意。

## Unresolved：5 個 destination reference

以下 5 個 PC 在相同 bounded window 中沒有完整的 literal source／DAD／CNT
連續形狀，因此沒有硬猜 source：

- `0x080abd80`：OBJ base 作為 arithmetic operand，source／destination register
  provenance 未閉合。
- `0x080ac1b0`：runtime pointer arithmetic 後寫入 DMA-related fields，未形成
  完整 literal source block。
- `0x080d5514`：source 由前置 arithmetic 計算，control／store 跨 shared block。
- `0x080d5f8e`、`0x080d61f2`：source／destination literal 後接 shared branch，
  bounded target window 沒有本地 CNT store。

這些是精確的 static negative，不是「沒有 DMA」或「沒有文字」的全域結論。

## Runtime 封鎖紀錄（非遊戲陰性）

`m112_obj_runtime.py` 已加入可重現的單一 GDB connection 流程：fresh A5TJ
process、12 個 breakpoint、DMA3 SAD/DAD/CNT watch、KEYINPUT scheduler，按鍵
序列 `a,start,a,b,down,a,right,a`，只輸出 PC/LR/register、source class、
bounded hash／length／count。這次沒有把連線失敗寫成自然 hit 或 0 hit：

- sandbox 內第一次連線在 socket 建立階段回報 `PermissionError: [Errno 1]
  Operation not permitted`。
- 以已授權 escalation 啟動本 session mGBA 後，headless 既有預設 `2367` 與
  Qt／替代 `2345` 連線均回報 `OSError: [Errno 49] Can't assign requested
  address`；沒有收到 GDB stop、沒有安裝 breakpoint/watchpoint 證據。
- 重用本機既有 port shim 時，shim 只輸出 loaded 後 process 立即退出；沒有
  修改或重編譯 shim，也沒有停止其他 session。

因此本回合 runtime status 是 `environment_blocked_before_gdb_attach`，不是
`natural_transition_negative`。後續若 socket/listener 可用，仍需以同一工具
補足 source register、DMA consumer 與畫面 hash；在此之前不得把 7 條 static
edge 升格為 runtime glyph chain。

## 分層結論與下一個缺口

### Confirmed

- 7 個 `0x06010000` bounded DMA3 source／destination／control field sequence。
- `0x02001000 → 0x06010000` 出現在 `0x080bd136` 與 `0x0813efce` 兩條 static edge。
- 12 個 reference 的 7/5 match split、source class 與 unresolved PC 集合可由
  工具重抽取。

### Provisional

- EWRAM source 是 staging／runtime buffer candidate；ROM `0x081b13b8` 是 data
  pointer candidate。兩者都沒有文字 identity。
- `0x02001000` 可能承載 OBJ asset，但尚無 producer、code-unit、transform 或
  OAM glyph 因果證據。

### Negative／blocked

- 本回合沒有自然 runtime stop，因此沒有宣稱 source register／glyph hit。
- 仍無 codepage、stable string ID、控制碼、source table、翻譯 ledger 或可靠
  回插路徑。

下一個最小 static 缺口是沿 `0x02001000` 的既有 LZ77／EWRAM writer 與
`0x0813efce` caller 向上最多三層，將 source class 分成 ROM pointer、RAM
runtime table 或 code-unit argument；若取得 code-unit，再建立 decoder proof，
否則轉向下一個可命名 text consumer。runtime listener 恢復後，優先重跑同一
bounded probe，不改變自然 transition 及證據分層。
