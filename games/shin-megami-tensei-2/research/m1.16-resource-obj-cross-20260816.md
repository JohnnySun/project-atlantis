# M1.16：命名 resource set 與 Start OBJ frame 交叉證據

狀態：`confirmed`（有界 negative），不是文字格式解出，也不是翻譯里程碑。

## 範圍與重現

本回合只重放 M1.14 已確認的 `0x0813ef65` callback records（16 組 × 8 筆，
共 128 筆），使用 M1.15 的 GBA 4-bit Huffman → nested LZ77 decoder；不做全
ROM glyph scan，也不輸出 raw ROM、compressed/decompressed bytes、圖片或完整
日文。最後 payload 只在工具記憶體中與一次已知 Start 後畫面的 active OBJ
sprites 比對。

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -B \
  games/shin-megami-tensei-2/tools/m116_resource_obj_cross.py \
  --rom /private/tmp/smt2-a5tj.gba \
  --vram /private/tmp/smt2-m15-start/vram.bin \
  --oam /private/tmp/smt2-m15-start/oam.bin \
  --output /private/tmp/smt2-m116-resource-obj.json
```

固定 capture metadata：VRAM SHA-256 `da8ed38455e15f6063941fe59f72c3d01985bdbee849c2b79d79899b5ee0b108`；
其 OAM 與 report 同一個 Start-screen capture。工具另記錄 ROM/OAM hash，避免把
其他 boot snapshot 誤當成此畫面。

## 結果

- active OAM：46 個 sprite、84 個 unique tile、184 個 tile occurrences。
- 比對資源：128 筆命名 source；Huffman header `0x24` 為 128/128，nested
  LZ77 header `0x10` 為 128/128；final output 皆 4096 bytes，unique output
  hash count 為 122。
- 以 32-byte tile alignment 比對完整 sprite bytes：exact、hflip、vflip、
  rotate180、nibble-swap 五種 family 均為 0 hit（46 個 sprite references）。
- 以同一 alignment 比對非零 4bpp tile：0/184 occurrences 命中；unique
  non-zero tile 也沒有命中。

## 證據分層

### Confirmed

1. M1.15 的命名 128 筆 source set 可重現解碼，且本回合不是依賴肉眼 OCR。
2. 在這個明確 Start capture 與 exact 32-byte aligned comparison window 中，
   命名 final payload 沒有直接提供畫面中 active OBJ sprite／非零 tile 的 byte
   match。

### Provisional

這批 nested resource 較可能是另一類資源／bank，而不是本次 Start frame 的直接
OBJ source。這個 negative 不能把它們全域分類成「非文字」，也不能排除另一個
staging bank、runtime transform 或未命名的 text consumer。

### Unknown／封鎖

文字 code-unit、stable string ID、codepage、控制碼、字寬與可回插 source table
仍未知；因此不建立 translation ledger。下一個最小切片應追已命名的文字／code-unit
consumer 或其 ROM/RAM table reader，而不是再擴張這批資源或重跑全 ROM glyph scan。
