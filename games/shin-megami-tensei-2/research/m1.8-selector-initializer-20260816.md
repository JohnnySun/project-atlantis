# M1.8 selector table initializer 與自然 transition（2026-08-16）

本回合只保留位址、PC/LR、寄存器 metadata、長度、hash、count 與有界陰性。
ROM、savestate、VRAM/OAM dump、圖片與完整原文均留在 `/private/tmp` 或本機
runtime，不進 Git；沒有建立 source table、ledger 或翻譯。依
`gba-localization` 的 source／working／ledger 分離規則，本回合沒有任何可提交
原文。

## 觀測界線

- ROM 為 A5TJ，8 MiB，SHA-256
  `819a6a19a40bfbe7608f4b813dc18285c827f64e1523561ffe8e10ce8ab5991e`。
- 工具 `tools/m18_initializer_probe.py` 使用 `core/gba/gdbstub_client.py`，每次
  只連一個本 session 的 mGBA GDB stub；runtime report 只寫 metadata。
- fresh process 在 GDB 初始讀取時為 `pc=0x00000000`、`cpsr=0x0000001f`；先安裝
  `0x03006950`／相鄰 halfword、`0x0203db40` 與 KEYINPUT watches，再 continue，
  因而這些 capture 是從 fresh runtime 起點 arm 的，不是畫面完成後 snapshot。
- GDB 標準 `R` reset packet 在 Qt mGBA 0.10.5 回覆 `E07`，不能用同一 process
  重播 reset；這是工具能力限制，不是把 table 直接寫入的理由。每條 capture
  都改用停止自己的 mGBA、重新啟動 A5TJ、單一 connection 的方式。
- `--initializer-only` 只保留 initializer candidates 與窄 table watches；
  `--key-sequence` 的 writes 僅是 KEYINPUT consumer 的輸入寄存器覆寫，工具沒有
  selector table/state write、selector index override 或 synthetic dispatch 選項。

## Static candidate mapping（provisional）

對齊的 literal／BL bounded pass 沒有做 glyph pattern scan：

- ROM 內 `0x03006950` 的 aligned word occurrences 為 157，Thumb literal-load
  refs 為 165；`0x0203db40` 對應為 212／214。這些 counts 包含資料區的偶然
  bit pattern，不能直接升格成 code refs。
- 以 literal load 後 0x10 bytes 內的 Thumb store、loaded base register 相符及
  ARM7TDMI Thumb prologue 交叉過濾後有 22 個 store candidates。它們仍是候選，
  因為同一 ROM literal 可能落在 data／未對齊的反組譯假陽性。
- 最集中且有 caller evidence 的 function candidates：

  | candidate function | global store PCs | width | bounded direct BL caller count |
  | --- | --- | ---: | ---: |
  | `0x0812f2b4` | `0x0812f2e8`, `0x0812f386` | 2/4 | 5 |
  | `0x0813e184` | `0x0813e22a` | 4 | 4 |
  | `0x0813e428` | `0x0813e458`, `0x0813e482` | 4/4 | 7 |
  | `0x0813e574` | `0x0813e5b2` | 4 | 3 |

  另有 `0x08132208`、`0x08132464`、`0x08132acc`、`0x08134ba8`、
  `0x081375d4`、`0x0813b2c0`、`0x0813d814`、`0x0813db34` 等單一 caller 未
  解析或無 direct caller 的 candidates。工具保留每個 function/store 的
  address、prologue、hash、width、source register 與 caller callsite；不把它們
  命名成真正 initializer。
- `0x0812f2b4` 的兩個 store 形態特別值得下一個靜態 source/state slice 追蹤：
  一個是 halfword、另一個是 word，且同一 function 有 5 個 direct callers。
  目前尚不知道其 `r0`／`r2` 來自哪個 ROM state table 或 runtime argument。

## Natural runtime cohorts（negative for this boundary）

| path | window / stops | input evidence | selector/global watches | selector/target hits | screen metadata |
| --- | --- | --- | --- | --- | --- |
| `boot-start` | 35 s / 117 | 18 KEYINPUT reads；idle 尚未送鍵 | pointer 0、counter 0 | 0 / 0 | VRAM hash `1fb8cccdb39a7969d06e36c0002b561ba7ba...`、OAM hash `16c4fc28...` |
| `fast-start` | 30 s / 98 | `a,start` 完成 | pointer 0、counter 0 | 0 / 0 | VRAM hash `1fb8cccdb39a7969d06e36c0002b561ba7...`、OAM hash `16c4fc28...` |
| `aggressive-start` | 45 s / 151 | `a,start,a,b,right,left,down` 送出 | pointer 0、counter 0 | 0 / 0 | VRAM hash `da8ed38455e15f6063941fe59f72c3d01985bd...`、OAM hash `fd3d2972...` |

同一 `aggressive-start` path 的 initializer-only hold/release follow-up 為
55 s、300 stops、300 KEYINPUT reads、8 個 transition 完成；窄 pointer/counter
watches 仍為 0，22 個 candidate function breakpoint 也為 0。這是同一路徑的
instrumentation follow-up，不新增第四條 transition cohort；它確認前一版 full
dispatch watches 的 0 hit 不是 callback breakpoint budget 造成的。

所有 capture 的 watchpoint install failures 都是 0。自然 queue/resource
callbacks 在 full probe 中仍可命中，但 selector entry、三個 selector callers、
`0x080ad0fc` 的 descriptor source 與 descriptor callback chain 在這些 path 沒有
自然命中；不能以先前 M1.7 synthetic `group=1,index=7` 代替。

## 分層結論

- **confirmed**：fresh process 可在 PC=0 起點先 arm watch；pointer global、counter
  與 adjacent span 的窄 watch 可安裝；三個 natural path 的實際按鍵／時間窗／
  screen hash；這些窗口沒有 `0x03006950`／`0x0203db40` write hit，也沒有
  selector/descriptor hit；GDB `R` reset 回覆 `E07`。
- **provisional**：22 個 literal-load/store candidates；`0x0812f2b4`、
  `0x0813e184`、`0x0813e428`、`0x0813e574` 是下一個 static source/state
  mapping 的優先 function，但尚未有 runtime PC/LR 命中。
- **unknown**：真正 reset／boot initializer、RAM table base、entry index/value
  的自然 writer；自然 selector 7／`0x081869c8`；第一個 descriptor consumer；
  glyph writer、source pointer、code-unit、Unicode identity 與 codepage。
- **negative（有界）**：本回合指定的三個自然 transition 及同一路徑窄 follow-up
  沒有 initializer 或 selector evidence。這不代表全遊戲沒有，也不再延長同一
  reset→Start 導航窗口。

## 下一個最小缺口

沿 static candidates 的 direct callsites 做 bounded ARM7TDMI／literal／參數
mapping，優先 `0x0812f2b4` 的 5 個 callers，再看 `0x0813e428` 的 7 個 callers；
只輸出 source register provenance、ROM literal address、caller hash 與 state
argument classification。若能從靜態 caller 得到 ROM state-table pointer，再用
單一 fresh runtime 在該 caller function entry 設 breakpoint，取得自然 input
state；若仍無 caller hit，就維持 negative，不對 table 或 CPU state 做 override。
只有自然 selector/descriptor consumer 接通後，才回到 `0x080baef0`／OBJ glyph
因果鏈與 source-table 解碼。
