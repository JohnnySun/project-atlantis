# M1.28：item family 的 bounded code-unit identity cross-map

日期：2026-08-16

## 範圍與外部參考

本回合只審核 M1.27 已確認的 `0x08198b74` shared table 前 8 筆，沒有掃描全 ROM、
沒有輸出 unit values、完整日文、圖片、glyph bytes 或 translation ledger。工具在
記憶體內使用 8 筆公開日文 item anchor 做 identity comparison，報告只保留
address/hash/length/count/match。

外部資料只作 category/order cross-check，不作 A5TJ raw source：

- Nintendo 日文說明書（PDF 第 13–16 頁）列出武器、彈丸、防具與道具名稱：
  `https://www.nintendo.co.jp/data/software/manual/WUP-N-JBRJ-JPN.pdf`
- 日文社群的各種資料表列出 item index `00` 起的順序；它是 SFC reference，不能
  取代 A5TJ ROM source：
  `https://wikiwiki.jp/snes007/%E7%9C%9F%E3%83%BB%E5%A5%B3%E7%A5%9E%E8%BB%A2%E7%94%9F%E2%85%A1%E3%80%80%E5%90%84%E7%A8%AE%E3%83%AA%E3%82%B9%E3%83%88`
- GBA 專頁確認本作品番 `AGB-P-A5TJ`，並把 GBA 版資料與其他版本分開：
  `https://w.atwiki.jp/shinmegamitensei2/pages/378.html`

說明書的前段 item sequence 與社群 table 的 `00..07` 順序一致；本回合只拿它們
當公開 anchor，沒有將 SFC table 的後續名稱直接灌入 GBA 翻譯資料。

## Reproducible probe

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -B \
  games/shin-megami-tensei-2/tools/m128_item_crossmap.py \
  --rom /path/to/A5TJ.gba \
  --output /private/tmp/smt2-m128-item-crossmap.json
```

schema：`smt2.m1.28.item-crossmap.v1`。

固定範圍是 table `0x08198b74`、stride `0x24`、caller-bounded 208 records、field
`+0x14`，只比較 ordinal `0..7`。每筆都保留 field hash、fixed-field length、
zero termination class 與 identity match；不保留 `observed_text` 或 unit sequence。

實際 A5TJ 結果：

- table window：7488 bytes，hash
  `77f7e001fcf190fdb7e6ed3018eab438e02d9a47e11630780f8dfb40eae5bdc8`。
- 8/8 個連續 fields identity match；觀察到的 unit counts 依序為
  `7, 7, 8, 7, 7, 5, 5, 5`，與 anchor 的字元長度一致。
- 前四筆可對應說明書的 `アタックナイフ`、`スパイクロッド`、`クィーンビュート`、
  `バトルハンマー`；後四筆也與同一公開 item sequence 對上。報告只輸出
  `item-sequence-00..07`、record address、field hash 與 boolean，不輸出這些
  field 的 unit/source payload。
- 31 個 custom unit identity 在這 8 筆 anchor 內被固定；identity manifest hash
  `0f9ab33ca411aec97d16a0f675868984435f98a0ea6c53582a320d59a605c6fc`。這不是完整
  codepage，也不是其餘 table 的 Unicode map。

## Evidence 分層

### Confirmed

- `0x08198b74` 前 8 筆連續 record field 與公開日文 item sequence 精確對上；這是
  code-unit identity 與 item-category 的第一個非 OCR semantic edge。
- `m28-item-record-{ordinal:04d}` 是可重抽取的 table-local stable ID formula，
  其 addressing 沿用 M1.27 的 `0x24` stride／`+0x14` field contract。
- 8 筆 anchor 使用的 31 個 custom unit 可建立有限 identity map；小ィ與長音符的
  差異也由 field identity 直接驗證，沒有用肉眼 glyph 猜測。

### Provisional

- 由於只有前 8 筆做語意 anchor，整個 208-record table 的 item family label 先標
  provisional；必須再確認武器／彈丸／防具／消耗品等 subcategory boundary。
- anchor map 只服務可審核 identity proof，不可當成完整遊戲 codepage 或翻譯字典。
- `0x08198eb4` secondary `0x20` window 尚未與 item table 建立關係。

### Negative / unknown

- 沒有 runtime capture；自然 item selector、live record pointer、scene 與 UI path
  仍未知。
- 208 筆其餘 record 的語意、完整 codepage、control code、width rule、glyph
  addressing 及可靠回插契約尚未確認；M2 ledger gate 維持 blocked。

## 下一個最小缺口

沿同一 table 只做 bounded subcategory boundary probe，優先交叉前 8 筆之後的第一個
record run 與 item list 的武器／槍彈／防具轉折；另選 `0x0819cb74` 的 skill accessor
建立獨立 anchor family，避免把 item、skill、demon table 混成一張 ledger。完成完整
stable ID、可逆 unit encoder、控制碼與寬度 contract 前，不開始翻譯。
