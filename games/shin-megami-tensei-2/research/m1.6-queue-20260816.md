# M1.6 固定 DMA、resource queue 與 staging writer 有界證據（2026-08-16）

本紀錄只保存可重現的位址、函式邊界、寄存器 metadata、hash 與 count；不保存
ROM、完整日文、raw RAM/VRAM/OAM dump、tile bytes 或圖片。runtime report 留在
`/private/tmp`，本作工具只讀取本機 ROM 來解 literal／計算 hash，不把 ROM 寫入
repository。

## 方法與界線

- 目標是 A5TJ，ROM SHA-256 `819a6a19a40bfbe7608f4b813dc18285c827f64e1523561ffe8e10ce8ab5991e`，8 MiB；ROM 未修改。
- 靜態驗證使用 `tools/m16_queue_probe.py --static-only`，只檢查八個已知
  `0x06013000` literal site、Thumb pointer refs、direct BL callers、queue contract
  與固定 staging candidate；沒有再做全 ROM glyph pattern scan。
- runtime 使用 core `core/gba/gdbstub_client.py`，本作 mGBA 0.10.5、獨立 GDB
  port `2367`。一次連線的 bound 是 wall 35 秒、最多 220 stop、最多保存 80 筆
  metadata event；按鍵 watchpoint 命中後送出 active-low Start `0x3f7`。
- 新工具輸出欄位限於 address、PC/LR、`r0`–`r3`、length、hash、region、offset、
  transfer units、selected field 與 count。停止封包、raw register dump 與 bytes
  不寫入 output。

## `0x080baecc` 函式邊界與 DMA3 組裝（confirmed）

這不是以畫面猜出的 source，而是 ROM instruction/literal 的直接解碼：

```text
080baecc  ldr r1,[pc,#0x10]  ; [080baee0] = 040000d4, DMA3 SAD
080baece  ldr r0,[pc,#0x14]  ; [080baee4] = 02001000
080baed0  str r0,[r1]        ; DMA3 SAD <- 02001000
080baed2  ldr r0,[pc,#0x14]  ; [080baee8] = 06013000
080baed4  str r0,[r1,#4]      ; DMA3 DAD <- 06013000
080baed6  ldr r0,[pc,#0x14]  ; [080baeec] = 84000700
080baed8  str r0,[r1,#8]      ; DMA3 CNT <- 84000700
080baeda  ldr r0,[r1,#8]
080baedc  bx  lr
080baede  alignment padding
080baee0  literal pool start
080baef0  next function entry
```

`080baedc` 是最後一條指令；`080baede` 是 code boundary，兩 bytes padding
後才是 literal pool。instruction pattern hash 為
`3381697ee1d4b5f1876f5675b66507c28e77855815d5966c28fc9691a9e63fce`。
因此 `0x02001000 → 0x06013000` 是這個 routine 的固定常數，不是 queue entry
或呼叫參數。`0x080baecd` 的 Thumb pointer 在 ROM file offset `0x0baf78` 出現
一次；對 `0x080baecc` 的 direct Thumb BL caller count 是 0。這個 pointer/data
reference 只能證明可能的 indirect table 使用，不能單獨證明 runtime 選中了它。

同一 instruction pattern 的七個固定副本如下；`source_store_pc` 是第一條
source `STR`，所以其中五個 site 名稱比真正 entry 大 4 bytes：

| 名稱 | entry | source store | source | destination | DMA3 CNT | pointer-ref count |
| --- | --- | --- | --- | --- | --- | ---: |
| `obj_dma_0baecc` | `0x080baecc` | `0x080baed0` | `0x02001000` | `0x06013000` | `0x84000700` | 1 |
| `obj_dma_0bb318` | `0x080bb318` | `0x080bb31c` | `0x02001000` | `0x06013000` | `0x84001200` | 1 |
| `obj_dma_0bb61c` | `0x080bb61c` | `0x080bb620` | `0x02001000` | `0x06013000` | `0x84001200` | 1 |
| `obj_dma_0bbcdc` | `0x080bbcd8` | `0x080bbcdc` | `0x02001000` | `0x06013000` | `0x84000d00` | 2 |
| `obj_dma_0bc588` | `0x080bc584` | `0x080bc588` | `0x02001000` | `0x06013000` | `0x84000e00` | 1 |
| `obj_dma_0bc97c` | `0x080bc978` | `0x080bc97c` | `0x02001800` | `0x06013000` | `0x84000c00` | 1 |
| `obj_dma_0d8d84` | `0x080d8d80` | `0x080d8d84` | `0x02001000` | `0x06013000` | `0x84000c00` | 1 |
| `obj_dma_0d944c` | `0x080d9448` | `0x080d944c` | `0x02001000` | `0x06013000` | `0x84000e00` | 1 |

八個副本的 instruction hash 相同；八個 direct BL caller list 都是空。這只
收斂了固定 consumer candidates，沒有把任何一個宣稱為免責畫面的實際 glyph
consumer。

## `0x080baef0` staging candidate（provisional）

`0x080baef0` 有合法 `push {r4,lr}`／stack frame 與兩次 BIOS
`LZ77UnCompWram` wrapper (`0x0815cb00`) call：

- 第一次 source literal `0x081839f4`，destination `0x02001000`。
- `r4 += 0x1000` 後第二次 source literal `0x081845e4`，destination
  `0x02002000`。
- `0x080baf0c` 後還有初始化／分支呼叫；完整 bounded instruction-window hash
  為 `710ff67ace9c816e59d579cae0fab5b1744fddbeb516e72161b0a255e560c131`。

這使它成為目前最精確的 glyph staging candidate，但不能稱為 writer：本次
reset→Start runtime 沒有命中 entry、兩個 staging destinations 或 `0x02001000`
write watch。附近 `0x080baf7c` 則是另一個 fixed setup，source `0x02001000`、
destination `0x0600e000`、control `0x84000800`，不是 OBJ `0x06013000` candidate。

## 通用 resource/event queue（confirmed as queue, not as glyph path）

`0x080ad01c` 的 drain 與 `0x080ad0fc` 的 producer 共同使用：

| 欄位 | 證據 |
| --- | --- |
| entry base | `0x02009004` |
| entry count | 64 |
| entry stride | `0x64` |
| state/type/argument | `+0x00` / `+0x02` / `+0x04` |
| progress/source/sentinel | `+0x10` / `+0x14` / `+0x20` |
| callback table | `0x0815eeec` |
| dynamic dispatch sites | `0x080ad070`, `0x080ad0a2`, `0x080ad0be` |
| free-slot helper | `0x080ad0d4` |

producer 會找 free slot、寫 entry metadata，再以 DMA3 SAD `0x040000d4` 和
control literal `0x85000019` 搬 metadata；這個 DMA3 transfer 的目的地是 queue
entry，不是 OBJ VRAM。bounded drain／producer 反組譯沒有發現獨立、循環遞增的
head/tail slot；實際被 drain consumed 的 queue state 是 entry `+0x00`，所以工具
只 watch entry flag 與兩個 live observed entries，不虛構 head/tail 位址。

reset→Start formal report（`/private/tmp/smt2-m16-runtime-formal.json`）的可重現
摘要：

- `keyinput_read_hits=6`、`start_sent=true`、`stopped_reason=event-or-wall-limit`。
- queue producer 2 hits：source `0x08509cf8`（file `0x00509cf8`）與
  `0x08509cd0`（file `0x00509cd0`），LR 分別回到 `0x080d5af1`／`0x080d5af9`。
- live entries 是 `0x02009068`（type `1`）與 `0x020090cc`（type `2`），其
  `+0x14` source pointer 正是上述兩個 ROM address；entry hash 隨 progress
  更新，但沒有保存 entry bytes。
- callback dispatch 30 hits；queue callbacks 只證明 resource/event activity，
  尚未連到 glyph staging。
- `0x0815cb00` 1 hit：source `0x084f9cd0`（file `0x004f9cd0`）、destination
  `0x0200f874`、decoded output length `2624`，不是 `0x02001000`。

## Watchpoint 與 negative window

formal probe 從 reset arm：

- staging `0x02001000` write watch：0 hit。
- queue entry watches：`0x02009068`、`0x020090cc` 各有一次 metadata stop。
- DMA3 SAD/DAD/CNT watch：metadata counts 分別 48／47／47；store value 以
  stop PC 前的 Thumb `STR` source register 解碼，不把 I/O readback 當成寫入值。
- 八個 fixed OBJ-DMA source-store／entry sites：0 hit。
- `0x080baef0` staging candidate：0 hit。

這個結果與 M1.5 的 OAM／VRAM 消費證據相容：畫面確實使用 OBJ tiles，但在
本次 reset→Start 狀態窗口，OBJ tile 的最早 writer 不是上述固定 candidates，或
其寫入發生在本 probe 可見窗口／watchpoint 之外。這是有界 negative，不是全遊戲
negative；不得由此推出未壓縮、固定 codepage 或不存在 source table。

## 間接資料表與下一個最小追蹤點

ROM/static data 還有一個可精確收斂的 indirect path：runtime `0x081869c8`
（file `0x1869c8`）的 structured descriptor table 含 Thumb pointer
`0x080baef1`，附近 records 也含 `0x080bafb9`；table pointer 可由 runtime
`0x08182b70`（file `0x182b70`）的 data reference 取得。這些是 descriptor/data
references，不是 direct callers，也沒有在 reset→Start formal run 自動選到
`0x080baef0`。

下一個最小切片是對 descriptor selection／indirect callback 設 breakpoint，live
讀取其 function pointer、source argument 與 destination，再只追 1–3 層 caller
直到 argument 變成 ROM pointer、RAM runtime table 或 code-unit/index。若仍不命中，
應改變可觸發的 resource transition，而不是再掃全 ROM glyph bytes。

## 分類與翻譯門檻

- **confirmed**：固定 DMA 的 ARM7TDMI 邊界／literal pool／參數組裝；八個
  fixed-copy pattern；generic queue producer／drain／entry layout；formal
  reset→Start 的 queue、DMA3 與 LZ77 metadata。
- **provisional**：`0x080baef0` → `0x02001000`／`0x02002000` 的 staging candidate；
  descriptor table 中的 `0x080baef1` indirect reference。
- **negative（有界）**：本窗口八個 OBJ-DMA site、staging writer entry、
  `0x02001000` write watch 均 0 hit；唯一 captured LZ77 destination 非 staging。
- **blocked**：尚未取得 glyph source/staging → transform → OBJ VRAM → OAM
  因果鏈、stable string ID、codepage、控制碼、source table 或可逆回插路徑；
  不開始翻譯。
