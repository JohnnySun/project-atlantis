# M1.15 nested Huff/LZ77 source class（2026-08-16）

## 範圍與重現

本回合只讀 M1.14 已確認的 `0x0813ef65` callback runs：16 組、每組 8 筆、
共 128 筆 `+0x04` ROM source pointer。沒有做全 ROM glyph pattern scan，沒有
讀取其他未命名 source region，也沒有輸出 compressed/decompressed bytes、raw
tile、圖片、完整日文或翻譯 source table。

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -B \
  games/shin-megami-tensei-2/tools/m115_source_class.py \
  --rom /private/tmp/smt2-a5tj.gba \
  --output /private/tmp/smt2-m115-static.json
```

工具只保存 address、header、tree／stream boundary、consumed length、hash、
decoder status、entropy、zero／FF count、4bpp tile block count 與 group summary。
ROM identity 仍以 `research/recon-20260816.md` 為準。

## Confirmed decoder chain

1. 每一筆 source 的首 byte 都是 `0x24`：高 nibble 是 GBA Huffman format `0x2`，
   低 nibble 是 4-bit data unit。tree field 以
   `tree_length = (tree_field << 1) + 1` 計算，compressed stream 位於 tree
   後並保持 4-byte alignment；128/128 的 tree walk 都可在 declared output
   length 內完成。
2. Huffman decoder 依 ROM 實際 writer 所消費的 BIOS contract 實作：node pointer
   先對齊到偶數位址，low six flag bits 選 child base，bit 7／6 分別標示
   left／right leaf，4-bit unit 以低 nibble 先寫入 destination byte。每筆都
   取得可重現的 input-span hash 與 Huff output hash；沒有把 Huff output 寫到
   repository。
3. 每筆 Huff output 的首 header 都是有效 GBA LZ77 `0x10` stream。LZ77 decoder
   的 declared output length 128/128 都是 `0x1000`，並完成 bounded literal／
   back-reference walk；每筆 final output 都是 4096 bytes。
4. final output 的 4096 bytes 恰為 128 個完整 4bpp tile block，128/128 通過
   `length % 0x20 == 0`。這與 writer 的 `0x02001000 + (r2 << 12)` bank
   expression 形狀相容；它是 resource／asset class 證據，不是文字用途或
   glyph identity 證據。

## 分層結論

### Confirmed

- M1.14 的 128 筆 source candidates 不是未解格式：每筆可重現為
  `GBA 4-bit Huffman (0x24) → GBA LZ77 (0x10) → 0x1000-byte 4bpp resource`
  的 nested chain。
- Huff tree／LZ77 decoder 的輸入、輸出長度、hash 與完整性統計可在同一 A5TJ
  ROM 上重跑；工具輸出不含 payload。

### Provisional

- 這批 payload 是 staging-bank resource／asset class，且與 `r2` bank expression
  相容；尚未有自然 runtime event 證明它們在 Start 免責畫面中被選取。
- 4bpp alignment 可能符合圖形資源，但不等於實際畫面 glyph 或字型表。

### Unknown／negative

- 尚未取得 source pointer → code-unit／string ID、控制碼、字寬、Unicode 或
  glyph identity；source table、codepage、翻譯 ledger 與回插仍封鎖。
- runtime listener 仍沿用 M1.12–M1.14 的 attach 前 socket blocker；本回合只
  做 static decoder，不把 128/128 static success 當 natural runtime hit。
- 下一個最小缺口是 listener 恢復後，在單一路徑捕捉 source／staging／DMA／OAM
  的自然 consumer；若確認只是 graphics resource，必須轉向新的 text/code-unit
  consumer，而非把本批 4bpp payload 當文字。
