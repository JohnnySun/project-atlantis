# M1.5 OBJ 字型來源有界證據（2026-08-16）

這份紀錄只保存 hash、offset、計數、OAM metadata 與執行期寄存器；不保存 ROM、完整日文原文、raw tile、VRAM/EWRAM/OAM dump 或圖片。Start 畫面的三行日文免責文字只作為畫面消費結果，不把 OCR 或肉眼讀字當成 source table。

## 回合與輸入

- 目標是 A5TJ、8 MiB 日版 GBA ROM，ROM 身分與 SHA-256 沿用 `research/recon-20260816.md`；ROM 沒有被修改。
- 使用 session 專用 mGBA 0.10.5、GDB port `2367`。本回合沒有重新編譯或修改 mGBA。
- 標準 memory/OAM 操作使用 `core/gba/gdbstub_client.py`、`core/gba/capture_runtime.py` 與 `core/gba/render_oam.py`；A5TJ 的比對與 bounded trace 使用本目錄 `tools/`。
- `KEYINPUT` `0x04000130` 的 read watchpoint 穩定在 PC `0x080a9a0a` 命中；active-low Start `0x3f7` 可重現從 logo 進入免責畫面。

可重跑的核心分析命令（ROM 與 dump 僅可放在本機或 `/private/tmp`）：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -B \
  games/shin-megami-tensei-2/tools/analyze_obj_tiles.py \
  <A5TJ.zip-or-gba> /private/tmp/smt2-m15-start/vram.bin \
  /private/tmp/smt2-m15-start/oam.bin \
  --iwram /private/tmp/smt2-m15-start/iwram.bin \
  --ewram /private/tmp/smt2-m15-start/ewram.bin \
  --compression-alignment 4 --compression-max-output 0x40000 \
  --compression-max-candidates 20000 --compression-glyphs-only \
  --output /private/tmp/smt2-m15-analysis.json
```

`trace_dma_consumers.py` 與 `trace_swi_consumers.py` 都要求先以 A5TJ ROM 啟動本 session 的 mGBA GDB stub；它們只輸出寄存器 metadata、region、PC、offset 與計數。

## 畫面與 OAM 消費者

Start capture 的穩定統計如下：

| 區域 | 大小 | 非零 bytes |
| --- | ---: | ---: |
| VRAM `0x06000000` | `0x18000` | 4,226 |
| palette `0x05000000` | `0x400` | 61 |
| OAM `0x07000000` | `0x400` | 311 |
| IWRAM `0x03000000` | `0x8000` | 2,990 |
| EWRAM `0x02000000` | `0x40000` | 2,900 |

OBJ 使用 4bpp、8×8 tile、1D mapping、OBJ base `0x10000`。active OAM 有 46 個 sprite，全部是 2×2 tile，使用 84 個 unique tile，tile number 落在 `0x180`–`0x20f` 的範圍內。boot capture 的 OBJ charblock 非零 tile 數為 0；Start capture 變成 151，首個變化 tile 是 `0x180`（VRAM `0x06013000`）。這證明該畫面確實在狀態轉換期間取得 OBJ bytes，但沒有把來源誤認成 ROM table。

重複 glyph hash 有 6 組，涉及 13 個 sprite。這只能說明同一畫面有重複字形／圖形，不足以把任何 glyph 指派給日文 codepoint。

已確認的較早 OAM consumer 是另一條明確路徑：IWRAM 中 OAM buffer 的完整 0x400 bytes 在 offset `0x33f0`、bus address `0x030033f0` exact match；ROM 內 DMA3 setup 將 source `0x030033f0` 搬到 OAM `0x07000000`，control 為 `0x84000100`，目的地 stop 可在 `0x080a9b20` 附近重現。這是 OAM 的 source/consumer 證據，不是 OBJ glyph source 的宣稱。

## A：ROM／RAM byte-identical glyph 結果

`analyze_obj_tiles.py` 以 OAM 實際 tile 順序串成每個 2×2 sprite 的 128-byte glyph，再做完整 ROM search：

- 完整 sprite glyph exact match：`0/46`。
- 4 個可逆 bounded transform（horizontal flip、vertical flip、180-degree rotation、nibble swap）的 sprite match：全部 `0`。
- 個別 tile exact match：`18/84`；排除全零 tile 後只有 `11/84`。命中 tile 的非零 bytes 很少，offset 分散，屬於稀疏／隨機反例，沒有形成 glyph table。
- 因沒有兩個以上完整 glyph source offset，`font_table_candidate` 為 `null`，沒有可報告的 base、stride 或 bank。

同一組 active glyph 另對 runtime RAM 比對：

- IWRAM：完整 sprite glyph `0`；7 個 tile 命中全是全零 tile，非零 tile 命中 `0`。OAM 完整 buffer 的唯一 match 是 `0x030033f0`，與上節 OAM consumer 相符。
- EWRAM：完整 sprite glyph `0`；9 個 tile 命中中只有 2 個非零 tile，各只有 1 個非零 byte，bus offsets 是 `0x0203f204` 與 `0x0203f205`。這些是稀疏反例，不是可用字型來源。
- EWRAM 的有效讀取是以 mGBA 可接受的 `0x200` bytes 分塊完成，256 KiB、0 個 chunk error；不把單次 4 KiB `E06` 失敗誤當作零資料。

因此 A 未成立：目前沒有 byte-identical ROM font table，也沒有可逆 glyph source offset／stride。

## 壓縮與 runtime consumer negative

以 ROM 內 4-byte 對齊、最大輸出 `0x40000`、最多 20,000 candidates，對標準 GBA LZ77 (`0x10`) 與 RL (`0x30`) stream 做 bounded 解壓，且只搜尋完整 sprite glyph variants：

- candidates examined：6,079，未觸發 candidate limit。
- candidate counts：LZ77 3,918、RL 2,161。
- valid streams：LZ77 1,201、RL 2,161。
- `match_reference_counts` 為空，完整 glyph match 為 `0`。

這只是否定本回合的標準 LZ77/RL 假設，不能反推文本一定未壓縮；目前也沒有建立自訂壓縮格式或 source table。

為了往前追一層，另做三個 bounded runtime checks：

1. 四個 DMA channel 的 source/destination register write trace 共 158 個 register stops；79 個 destination stores 的 region counts 為 EWRAM 5、IWRAM 33、BG VRAM 5、palette 9、OAM 13、other 14，OBJ VRAM 為 0。這個回合有命中 KEYINPUT 13 次並送出 Start。
2. BIOS SWI vector `0x00000008` trace 有 120 次 vector hit；只見 SWI `0x0b` 66 次、`0x05` 53 次、`0x11` 1 次，所有 bounded SWI destination 都沒有落在 `0x06010000`–`0x06017fff`。已觀察的 SWI `0x0b` 範例是 ROM file offset `0x0e23f8` → IWRAM `0x03007000`，不是 OBJ glyph。
3. 對第一個實際文字 tile address `0x06013000` 設 1-byte write watchpoint，80 次 KEYINPUT read event 的 bounded 回合中 tile write hit 為 0；先前 4-byte watchpoint 也為 0。這是 mGBA memory-watch 行為的負面觀察，不宣稱已捕捉所有 DMA／PPU writes。

## Provisional 與下一個精確點

ROM file offset `0x0baecc`（runtime `0x080baecc`）有一個固定 DMA3 setup：

```text
source register  <- 0x02001000
destination      <- 0x06013000
control          <- 0x84000700
```

這個 routine 的數值與首個變化 OBJ tile 對得上，因此是目前最精確的 static candidate；但在 reset→Start 的 30-second execute-breakpoint trace 中沒有命中，所有固定 `0x06010000`／`0x06013000` literal reference breakpoints 也沒有命中。它目前只能標為 **provisional**，不能寫成免責畫面的 confirmed source。

下一個追蹤點已收斂為：找出實際 Start 狀態所選的 transfer queue／indirect DMA setup，從 DMA3 destination store 的 caller 往前記錄 source pointer；若 candidate `0x080baecc` 被選中，再於 transfer 前讀取 `0x02001000` 的 hash／非零統計，並與 `0x06013000`–`0x06017fff` 的 tile hash 做 bounded 對照。這一步之前不建立 source table、codepage、控制碼或翻譯 ledger。

## M1.5 分類

- **confirmed**：A5TJ identity；Start input consumer；OBJ/OAM/palette 畫面消費；OBJ charblock 在狀態轉換後改變；OAM IWRAM source 與 DMA3→OAM consumer；ROM/RAM exact glyph negative；bounded LZ77/RL negative。
- **provisional**：固定 OBJ DMA candidate `0x080baecc` → `0x02001000` to `0x06013000`；尚未在目標畫面 runtime 命中。
- **negative**：完整 glyph ROM/IWRAM/EWRAM match、變形 match、bounded LZ77/RL glyph match、目前四 channel DMA destination 的 OBJ hit、目前 BIOS SWI destination 的 OBJ hit、目前 byte-width CPU OBJ watch hit。
- **blocked by evidence boundary**：尚未有 stable string ID、可重抽取 source table、codepage、控制碼或可逆回插路徑；本作仍不可開始翻譯。
