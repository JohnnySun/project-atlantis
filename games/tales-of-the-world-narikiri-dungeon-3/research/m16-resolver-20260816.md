# M1.6 resolver live-edge boundary（2026-08-16）

本回合只保存 breakpoint／watchpoint metadata、指標分類、caller 位址、計數與
雜湊；ROM、sav、完整日文、RAM／VRAM raw dump 與圖片均留在本機 ignored 路徑。
本回合沒有翻譯、OCR、字型 identity 或回插變更。

## 1. bounded probe 邊界

`tools/consumer_probe.py` 新增 resolver mode，重用 `core/gba/gdbstub_client.py`，
不新增 transport 或 port shim：

1. 在 Thumb `0x08003444` 設 entry breakpoint，entry stop 記錄 `r0` table base、
   `r1` index 與 live `lr`。
2. 只在同一 call 的 `0x0800345C` return site 設短命 breakpoint，記錄 resolved
   `r0`；因此不把 entry register 的靜態推算當作 runtime return。
3. 以 strict extractor 的 8,938 個 record boundary 建 metadata index，只對五個
   已核准 windows 分類 resolved pointer。落在 window 但不是 strict boundary 的
   位址標為 `confirmed-window-nonstrict-offset`，不會升格成 string record。
4. `--trace-offset` 才會對一個指定 concrete source address 設 read watchpoint；
   `--trace-first-record` 是第一個實際返回的 strict record 的 bounded fallback。
   JSON 只輸出 string ID、offset、register、stop packet 與 count，不輸出 source
   bytes 或原文。

本回合獨立啟動 B3TJ mGBA headless process、GDB port `2346`，並在 client 結束後
停止該 process。測試 sequence 的總量為 224 個 KEYINPUT events：

```text
start:12, none:20, down:12, none:10, a:12, none:20,
right:12, none:10, a:12, none:20, left:12, none:10,
b:12, none:10, up:12, none:10, select:8, none:10
```

ROM identity 仍為 title `TOWNARIKIRI3`、code `B3TJ`、maker `AF`、revision 00、
CRC32 `1867CCEF`。完整 JSON 僅在 `/private/tmp/tow-nd3-m16-selected.json`。

## 3. selected record 與 source read

第二個 bounded run 對 selected `sjis:0x146EE0`（file offset `0x146EE0`、GBA
`0x08146EE0`、region `text-pool`）同時掛上 resolver entry breakpoint 與 source
read watchpoint：

| evidence | result |
| --- | --- |
| KEYINPUT stops | 224，皆為可重現的 `rwatch` at `0x04000130` |
| resolver entry／return pairs | 8；同上表，全部 window 外 |
| selected source read | **0 hits** |
| resolver-derived strict record | **0** |
| caller-return trace for a text record | 未啟動；沒有 eligible strict-window return |
| source read destination registers | 無，因沒有 source read stop |
| selected post-hit VRAM／glyph causality | 無；不能把 title baseline tile match 歸因給 selected record |

因此 `0x08146EE0` 仍是 **negative for this bounded normal navigation**。M1.5 的
direct-pointer provenance（`0x08DD1B9C`、12-word adjacent table）仍有效，但本回合
沒有把它錯接到 `0x08003444`。

## 4. navigation negative

為確認短序列沒有只是停在 title 初始化，曾以 runtime-only EWRAM state byte
override 做小範圍檢查：初始 state metadata 為 `0404FF00`；把下一 state byte
設成 1 或 2 後，分別觀察到 `0104FF00`／`0204FF00`，current state 仍為 4，PC
落在 IWRAM wait routine（`0x03003830` 或 `0x03003874`）。這不是正常遊戲流程
證據，也沒有寫回 ROM；它只說明目前 headless harness 尚未建立可審核的 state-4
到文字選單 transition。不得把這個 override 當作選單已進入的證明。

## 5. evidence classification

| item | status | boundary |
| --- | --- | --- |
| `0x08003444` entry／`0x0800345C` return | **confirmed-runtime** | live resolver pair 可重跑 |
| 8 個高位 resolved pointers 與 caller LR | **confirmed-runtime resource edge** | 全部 window 外；不是文字 |
| 五窗 strict boundary filter | **confirmed-tooling** | 只分類已知 windows，不做 broad pointer scan |
| selected `0x08146EE0` read watchpoint | **negative** | 224-event bounded navigation 0 hit |
| state-byte override | **provisional-negative** | 只反映 headless wait／未建立正常 transition |
| RAM decoder、destination buffer、glyph lookup、VRAM writer | **unconfirmed** | 沒有 text source read，不能推導 |
| codepage、控制碼語義、容量、回插、翻譯 | **unconfirmed** | 維持 M2 前禁止翻譯邊界 |

## 6. 下一個最小切片

不再擴充 resolver transport 或做新的全 ROM pointer scan。下一個最小 runtime
切片是把 `0x08005ECC` state dispatcher 設為單一 breakpoint，僅記錄正常流程的
state0／current-state byte、table-dispatched function 與 state transition；先
證明 state 4 離開後，再沿既有 `0x08003444` probe 重跑 `--trace-first-record`。
若 state 4 仍未離開，應先以一個可重現的 save／menu entry harness 解決 navigation
邊界，而不是把資源 resolver hits 或畫面 OCR 當成文字來源。

在取得一個 resolver return 落入五窗 strict record 且 source read 命中前，狀態仍是
「研究進行中、翻譯未開始」；本回合沒有證明 codepage、glyph identity 或可逆回插。
