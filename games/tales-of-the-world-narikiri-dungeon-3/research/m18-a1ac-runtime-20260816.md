# M1.8 A1AC register-write、edge 與 state-return bounded runtime

日期：2026-08-16

本回合只針對 B3TJ state 4 的一條正常 input path，沒有新增 runtime pointer
scan，也沒有寫入 state bytes、resource object 或 save。ROM 身分仍是
`TOWNARIKIRI3`／`B3TJ`／`AF`／CRC32 `1867CCEF`。正式成功 receipt 使用全新的
mGBA 0.10.5 process、單一 GDB connection、獨立 listener `127.0.0.1:2367`，載入
`/private/tmp` 的 ROM 副本且沒有載入 `.sav`；JSON receipt 留在 ignored
`/private/tmp/tow-nd3-m18.PqbtS2/`，沒有進 Git。

## confirmed-runtime

### 1. A030 completion gate 與正常 START

reset stop 時固定安裝 dispatcher、state return、A030/A050、A1AC callsite/entry、
edge、A2C0 與 caller-after breakpoint。第一個 dispatcher receipt 是：

| 欄位 | 值 |
| --- | --- |
| dispatcher | `0x08005ECC` |
| next/current/previous | `04` / `FF` / `FF` |
| dispatch table / entry | `0x08741D94` / `0x08741DA4` |
| resolved function | `0x08009C69`（Thumb `0x08009C68`） |

正常 setup 依序命中 `0x0800A58C → 0x0800A388 → 0x0800A030 → 0x0800A050`。
A030 的 runtime object 是 `0x0200C6DC`；由該 object 推導出的 completion
watch address 是 `0x0200C720`（`+0x44`）。在 A050 loop 掛 write watch，沒有
直接寫值。之後正常送一次 START active-low `0x03F7`，GDB response 是 `OK`，
再送一次 `0x03FF` release；completion write stop 位於 watched address，edge
IWRAM 值同時為 `0x00000008`（START bit 3）。這使 A030 正常返回，沒有 state
override 或 object override。

completion writer stop 的 caller/register context 是 `PC=0x08009ED2`、
`LR=0x080048D5`；`r4=0x03002B18` 是 writer context，不被誤記為原 resource
object。被 watch 的 target 仍以 `0x0200C720` 為準。

### 2. A1AC → A pulse/ACK → edge bit 0

正常 completion 後，A1AC callsite `0x0800A3E6` 命中，`r0=0x0200C6DC`；接著
entry `0x0800A1AC` 命中，`LR=0x0800A3EB`。A1AC 之後才保留 KEYINPUT read
watch，避免 state 4 初始化期間製造無界 stops。

在 `0x08000E12` 的 KEYINPUT read stop，目的暫存器確認是 `r1`：

| 階段 | `r1` 寫入 | GDB response |
| --- | --- | --- |
| pre-A1AC 正常 gate | `0x03F7`（START） | `OK` |
| pre-A1AC release | `0x03FF` | `OK` |
| live A1AC pulse | `0x03FE`（A） | `OK` |

每次 register write 使用 core client 的 `0.05s` packet delay 與一次 timeout
retry policy；本回合沒有 timeout 或 unexpected response。A pulse 後未額外
注入第二個 A，release 讀取上限仍為 3。

接續命中 edge check `0x0800A174`，`0x030033F8=0x00000001`，bit 0 為 true。
從該停點做 bounded single-step，PC 序列為
`0x0800A176, 0x0800A178, 0x0800A17A, 0x0800A17C, 0x0800A17E,
0x0800A180`，沒有跳離 true path。此處 `r7=0x0200C6DC`，object `+0x54`
讀值為 `0x00000000`；之後在 post-store `0x0800A18C` 讀到 `+0x54=0x00000001`。

### 3. A2C0 success、state return 與畫面 metadata

`0x0800A2C0` entry 的 `r0=0x0200C6DC`，其 `+0x54=1`；caller-after
`0x0800A3F0` 的 `r0=1`。這是本回合確認的 A2C0 success，不是把高位 asset
pointer 當文字資料。

接著命中 dispatcher common return `0x08005E12`。return 停點 state bytes 是：

| current | next | previous |
| --- | --- | --- |
| `0x04` | `0x07` | `0xFF` |

bounded stop count 為 16，termination 為 `normal-state-return`。同一停點只保存
固定 VRAM/palette/OAM 的 hash metadata：

| region | SHA-256 | non-zero bytes |
| --- | --- | ---: |
| VRAM `0x06000000/0x18000` | `39b5e2da6315e4a3c2a35a66fe631a3cea3d61cc0779a971ae619f0de369f0f4` | 51467 |
| palette `0x05000000/0x400` | `a5feaa14031885d0987a5d09c340520276d527558dad7d3edb8afdd36e0ee22e` | 427 |
| OAM `0x07000000/0x400` | `f248fae22c51ff8825ac0123e28ead5f056099eb92007745b7df43f89a2512a9` | 269 |

這確認 state 4 正常 return 及畫面狀態變化的 metadata；hash 本身不是 OCR，也
不是文字 source 或 glyph identity。

## provisional / unknown / negative

### provisional

- `next=7` 與畫面 hash 證明 state 4 正常離開；尚未證明 state 7 的特定畫面
  是哪一個 menu/event，也未把 hash 內容當作文字畫面。
- A1AC 的 object provenance 已由 A3E6 `r0`、A174/A180 `r7`、A2C0 `r0`
  三個 live context 交叉一致為 `0x0200C6DC`；writer stop 的 `r4` 則是
  不同的 writer context，不能用它替代 watched object。
- 單步只確認 edge branch 與 `+0x54` store；尚未定位 decoder、codepage、glyph
  lookup 或 VRAM text writer。

### negative

- clean trace-first 的四個 resolver return 全部五窗外，strict source read 是 0。
- 本回合沒有 source text read、RAM decoder、glyph identity、文字 VRAM 因果鏈。
- 沒有翻譯 ledger、回插 builder、容量／checksum round-trip 或 patch 產物。

### unknown

- state 7 內實際使用的事件／menu record 尚未選定。
- `0x08003444` 以外的真正 text consumer/caller 尚未證明；不應再從地址相近
  推論。

## 可重跑工具與邊界

M1.8 harness：

```sh
PYTHONDONTWRITEBYTECODE=1 /usr/bin/python3 \
  games/tales-of-the-world-narikiri-dungeon-3/tools/m18_a1ac_probe.py \
  games/tales-of-the-world-narikiri-dungeon-3/roms/base/Tales_of_the_World_Narikiri_Dungeon_3_JP_AGB-B3TJ-JPN.gba \
  --port <independent-b3tj-gdb-port> --per-stop-timeout 30 \
  --max-stops 64 --max-edge-checks 8 --release-reads 3 --max-steps 12 \
  --output /private/tmp/tow-nd3-m18-a1ac.json
```

它只在 A030 loop 後送一次正常 START，再在 live A1AC 後送一次 A；所有 GDB
register writes 都檢查 `OK`，並有固定 stop/step/release 上限。輸出不含 ROM
bytes、完整日文、save、raw RAM/VRAM 或圖片。

下一個最小切片是：以 state 7 的正常畫面為入口，沿既有 bounded resolver/caller
方法找到第一個真正落入五窗 strict record 的 text consumer；仍不可開始翻譯，
也不可擴大成全 ROM pointer scan。

## 同日 fresh standard mGBA receipt

為排除舊版自製 binary 的 port 狀態，另以乾淨 standard SDL/GDB build、全新 B3TJ
process 與單一 `127.0.0.1:2345` listener 重跑本 harness。這次沒有 state、object
或 save override；所有 register write 仍只發生在 KEYINPUT read stop：

| 項目 | receipt |
| --- | --- |
| termination | `normal-state-return` |
| stop count | `16` |
| A1AC entry hits | `1` |
| edge checks | `1`，bit 0 true |
| A2C0 entries | `2`，caller-after `r0=1` |
| state return | `0x08005E12`，current `0x04`、next `0x07` |
| pre-START / A / release | `0x03F7` / `0x03FE` / `0x03FF`，三次 response 均 `OK` |

這是獨立於早先 port `2367` receipt 的 confirmed runtime 重現；它仍只證明正常
state 4→7 navigation，不證明 state 7 使用哪一筆文字。隨後在同一 mGBA 0.10
process 建立第二個 GDB connection 時，stub 對 `qSupported` 無回應而 timeout；這
與 core client 已知的「0.10.x 第一個 client disconnect 後常不接受第二個
connection」限制一致。因此本次 formatter 仍未在 state 7 同一連線內執行，不能把
該 timeout 誤記為 text-consumer negative。下一步應在**同一 GDB connection**整合
正常 A1AC navigation 與 formatter trace，或以全新 process 從 reset 重跑該合併
流程。
