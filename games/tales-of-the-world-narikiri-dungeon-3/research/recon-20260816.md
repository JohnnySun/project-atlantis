# B3TJ 唯讀偵察與有界 runtime 證據（2026-08-16）

本文件只記錄研究結論、offset、位元組層級訊號與 runtime metadata，不保存完整
日文原文。日文原文表由 `tools/extract_strings.py` 在本機產生，輸出路徑
`research/tales-of-the-world-narikiri-dungeon-3-decoded.jsonl` 已被 `.gitignore`

## 2. 靜態方法與結果

`recon_rom.py` 的全 ROM 結構掃描仍只作候選產生器：合法 Shift-JIS 結構 run 有
183,371 個、對齊指標 run 候選 1,092 個、LZ77／Huffman／RLE magic 候選分別為
21,287／5,813／13,933 個。這些全域數字包含二進位假陽性，不能當文字覆蓋率。

最長的對齊指標候選位於檔案 `0xEC69A0`，1,002 個非遞減 word 指向檔案
`0x1489D8–0x1BE194`（span `0x757BC`）。它是值得 runtime 追蹤的資源／指令表
候選，不是已證明的字串表。

### 嚴格抽取器

`extract_strings.py` 只接受以下五個宣告區段：

| 名稱 | 檔案範圍 | 本次記錄數 |
| --- | --- | ---: |
| kana-and-names | `0x100000–0x103000` | 173 |
| names-and-ui | `0x105000–0x10D400` | 1,603 |
| battle-and-enemy-tables | `0x111000–0x114000` | 387 |
| text-pool | `0x140000–0x1C4000` | 6,532 |
| list-data-provisional | `0x1C8000–0x1CC000` | 243 |
| **合計** |  | **8,938** |

每筆記錄必須從區段起點或 NUL 邊界開始，以合法 Shift-JIS lead/trail、ASCII、
半形 kana、LF 或明確 `{HH}` 控制 token 組成，並在區段內遇到 NUL；`0xFF`、
非法 lead/trail、未終止內容與 ASCII-only 短片段會被拒絕。對齊的 GBA 絕對指標
只作附加 metadata，不會使非法字串通過。這一版是「可審核候選原文表」，不是
已完成的文本解碼器：codepage／renderer 尚未由 runtime 證明。

靜態上較有價值的訊號包括：`0x140000–0x1C4000` 的密集 NUL 記錄、LF `0x0A`、
`%s`／`%0t`／`%0g`／`%h`／`%k`／`%l`／`%d` 等格式 token，以及多個資料窗中
反覆出現的低控制位元組（包括 `0x12`）。目前只保存 bytes，不替任何 token 命名
或推定參數語義。

## 3. 有界 mGBA runtime 回合

環境是 mGBA 0.10.5；使用本專用 B3TJ 進程與獨立 GDB port `24387`。本回合的
通用 GDB packet client 是 `games/shining-soul-1/tools/gdbstub_client.py`，只作
transport；B3TJ 的 breakpoint 位址與資料解讀沒有套用其他遊戲格式。回合結束後
已確認本進程與 `24387` listener 均停止。

### reset／VRAM 寫入證據

- reset breakpoint `0x08000000` 命中：`pc=0x08000000`、`sp=0x03007F00`、
  `cpsr=0x2000001F`。
- 對 `0x06000000` 設 4-byte write watchpoint，命中 stop `T05watch:06000000;`；
  當下 `pc=0x080DD44E`、`lr=0x08003417`、`r0=0x087B5686`、
  `r1=0x06008000`、`r2=0x087AE6F8`。這是 wrapper 後的實際 VRAM 寫入，證明
  遊戲確實把 runtime 解壓／搬移結果寫到 VRAM；沒有證明內容是字型或文字。

## 4. 回插與風險結論

目前可行的下一個工程步驟是追蹤一個已知 UI／事件字串從指標或呼叫端到 glyph
搬運，再確認容量與控制碼。尚不可直接做大批翻譯或擴長回插，原因是：

1. 靜態 Shift-JIS 解碼與文字 renderer 尚未互相驗證；
2. `0x12` 等控制碼、LF 與格式 token 的參數／結束規則未知；
3. 指標候選未分類，無法保證改變 bytes 不會誤傷事件指令或資源表；
4. 壓縮 wrapper 已證明存在，但尚未證明文字使用哪一種壓縮或是否未壓縮；
5. 尚無等長／容量檢查、指標更新、ROM round-trip 與 runtime 回歸工具；
6. 本輪未可靠導覽到事件、戰鬥或文字畫面，輸入失敗只代表這次 runtime 邊界。

因此本里程碑是「格式偵察與 runtime 風險界線已收斂」，不是翻譯完成或回插可用。
