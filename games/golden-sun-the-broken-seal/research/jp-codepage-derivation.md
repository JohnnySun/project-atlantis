# 日文擴展碼表推導記錄（2026-08-15）

## 目標

《開啟的封印》(AGSJ01 Rev.00) 與《失落的時代》(AGFJ01 Rev.00) 共用同一套引擎與
Huffman 文字系統。為了比照第二部的做法從日版直接漢化第一部，需要一份可信的
「擴展字形 ID → Unicode」碼表，涵蓋日文基礎假名以外的漢字／符號字形。

## 陷阱：以 ID 直接沿用第二部碼表

第二部的 `codepages/ja-extended.tsv` 對第一部抽出的 11,115 條字串、297,027 個
字形單元做結構檢查，**100% 找到對應項**（`research/probe_codepage_reuse.rb`，
已刪除，結論記錄於此）。這個「全覆蓋」結果具有誤導性：擴展字形 ID 是**依各作
自己文字表中字元首次出現順序**個別配置的，不是共用資源。兩作偶然使用相近的
ID 區間（都在 0x100 起算），使得「每個 ID 都查得到字」，但查到的**字元不保證
相同**。

具體反例：以第二部碼表解碼第一部 id 14，得到「後名をおしえてください」——
「後名」不是有效日文詞。比對第二部語料，`名前をおしえてください`
（請告訴我你的名字）在第二部是 id 15，其「名」「前」恰好排在第二部 id 4
「ごうりゅう後のデータです」引入的「後」字之後（0x102=後, 0x103=名,
0x104=前）。第一部沒有「合流」（雙版本存檔合併）這個功能，文字表裡沒有這一句，
所以「後」字在第一部裡从未先被登記，導致第一部自己的 0x102／0x103 實際指向
完全不同的字元。

**結論：結構上 100% 覆蓋 ≠ 語義正確；不可以直接沿用另一款遊戲的擴展碼表。**

## 解法：以字形點陣比對取代 OCR

兩作字型渲染格式相同（`core/golden-sun/render-original-glyphs.rb`：擴展字形固定
24 bytes、12 列 × u16、寬度 10px），且極可能共用同一份原始點陣資源。因此不需要
OCR，只要在第一部 ROM 裡搜尋第二部已驗證字形的 24-byte 點陣即可還原對應字元：

1. 用第二部 `codepages/ja-extended.tsv`（152 個字形，狀態 provisional）在第二部
   ROM 的 `0x05bf8c` 建立「24-byte 點陣 → 字元」對照表。
2. 用「神」「殿」「名」「前」「力」「手」六個錨點字元，在第一部 ROM 逐位元組搜尋
   其點陣，全部各自唯一命中，且彼此間距固定為 24 bytes，落在
   `0x33b30, 0x33b48, 0x33b60, 0x33b78, 0x33e30, 0x33fc8`——證實第一部擴展字形表
   基底位址為 `0x33b30`，且字元出現順序與推論一致（神→殿→名→前⋯）。
3. 以 `tools/derive_codepage_by_raster.py` 對第一部 0x100–0x171（114 個擴展字形，
   由 `research/jp-text-ids.tsv` 中出現的最大字形 ID 決定）逐一比對點陣，**114/114
   全部命中**，寫出 `codepages/ja-extended.tsv`。

## 驗證（sentinel checks）

用新碼表重新解碼全部 11,115 條字串後，之前的可疑輸出全部變得語意通順：

| id | 舊（誤用第二部碼表） | 新（自有碼表） |
| ---: | --- | --- |
| 14 | 後名をおしえてください | 名前をおしえてください（請告訴我你的名字） |
| 26 | きろく前です | きろく中です（記錄中） |
| 2527 | ソル神殿名 | ソル神殿前（索爾神殿前） |
| 3441 | 後名とレベルです | 名前とレベルです（這是名字和等級） |
| 4645 | ⋯3信名に なくなったという⋯世さんの 後名 | ⋯3年前に なくなったという⋯兄さんの 名前（三年前過世的哥哥的名字） |
| 7243 | とうぞくの後も⋯地におちてしまったわ | とうぞくの名も⋯地におちてしまったわ（盜賊的名聲也一落千丈——「地に落ちる」是成語） |

再抽查基礎假名（0x20–0xff，引擎內建、與遊戲無關）解碼的存檔 UI 文字（id 0–13）
全部語意通順，確認基礎表可直接共用，不需重新推導。

## 產出

- `codepages/ja-extended.tsv`：第一部自有擴展碼表，114 條，狀態 provisional
  （點陣比對確認，非人工目視／OCR，可信度高於第二部初期的 OCR 投票結果，但仍
  標記 provisional 待逐句校對）。
- `tools/derive_codepage_by_raster.py`：可重複執行的推導工具。
- `research/jp-text-ids.tsv`、`research/jp-decoded.jsonl`：全量抽取與解碼結果
  （被 `.gitignore` 排除，不進版本庫）。

## 人名／地名跨作一致性

第一部與第二部劇情連貫，共用同一世界觀與大量人物、地名，玩家會先玩第一部再接
第二部，音譯若兩作不同會破壞連續感。以第二部 `translations/glossary.zh-TW.tsv`
（222 條術語）逐條在第一部全量解碼文字中做字串比對，**120 條**在第一部原文中
確實出現；其中 4 條被字串比對誤判為出現，經人工核對前後文排除：

| 詞條 | 誤判原因 |
| --- | --- |
| シン（角色「辛」） | 只出現在「アサッシンソード」「ダンシングマッシュ」等複合外來語中，非角色本身 |
| スサ（角色「須佐」） | 只出現在「デスサイズ」（死神鎌）中 |
| サンド（法術「潛沙」） | 只出現在「サンドイッチ」（三明治，NPC 對話梗） |
| まの海（地名「魔之海」） | 唯一命中是「いまの海」（今の海，"現在的海"），非「魔の海」 |

其餘 116 條（含前作／本作主角組七人：ロビン／羅賓、ジェラルド／傑拉德、
イワン／伊萬、メアリィ／米雅莉、ガルシア／加西亞、ジャスミン／潔絲敏、
シバ／西芭，皆見於第一部自己的角色命名清單 id 102–108，緊接編號 `PC07`
除錯標籤，確認為「可命名角色」清單。メアリィ／シバ 的中文譯名已於
2026-08-15 依社群主流核對結果改為「米雅莉」「西芭」，見下方名稱緩衝區
截斷 bug 一節）已寫入
`translations/glossary.zh-TW.tsv`，並修正原本以《失落的時代》視角撰寫的
「前作／本作」用語，改為明確指名，避免在第一部自己的術語表裡出現方向相反
的指代。工具：`research/build_shared_glossary.py`（可重複執行）。
