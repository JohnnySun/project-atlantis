# B3CJ M2.4 runtime handshake／static writer 收據

本切片針對 M2.3 的 runtime handshake 問題，先唯讀檢查 repo 其他成功 session
的啟動方式，再對本作 M2.3 POC ROM 做最多兩輪 fresh process 嘗試。採用的關鍵
差異是 `-C gdb.port=<high-port>`，不用已被證明不適用於本輪的
`ports.qt.gdbPort`；每一個 process 只允許一條 GDB connection，client 使用共用
`core/gba/gdbstub_client.py` 的 packet delay、ACK 與一次 timeout retry。

## 參考的成功模式

唯讀 review 了以下既有 session：

- `games/super-robot-taisen-d`：`-C gdb.port=24567 -C skipBios=1 -g`，以單次
  client 先送 `qSupported` 再讀 register／memory。
- `games/tales-of-the-world-summoners-lineage`：獨立高位 listener、一次連線、
  `core/gba/capture_runtime.py`，capture 後停止已核對 PID。
- `games/shining-soul-1` 與 `games/sangokushi-eiketsuden`：client 使用約
  50–80 ms packet delay，對 GDB ACK／timeout 做有界處理；受控 register write
  若使用，必須另標 `controlled`，不升格自然 reachability。

本作沒有把這些遊戲的 offset、文字或工具複製進來；只採其 transport／ownership
做法。

## Fresh process attempts

ROM 始終是 ignored `work/m2.3-poc.gba`，沒有啟動 clean ROM，也沒有附加其他
session。

| attempt | preflight／launcher | process／listener 收據 | handshake 判定 |
| --- | --- | --- | --- |
| 1 | `24763` bind preflight=`PORT_24763_FREE`；`/opt/homebrew/bin/mgba -C gdb.port=24763 -C skipBios=1 -g games/summon-night-craft-sword-3/work/m2.3-poc.gba` | PID `29811` 命令列經 `ps` 確認只指向本作 POC；startup 後 `24763` 沒有 listener，未建立 GDB connection | `runtime_m2_4.py` 對已停止的 `24763` 收到 `ConnectionRefusedError [Errno 61]` |
| 2 | `24764` bind preflight=`PORT_24764_FREE`；repo 其他成功 session 使用的 `/private/tmp/atlantis-mgba-headless-build2/mgba-headless -C gdb.port=24764 -C skipBios=1 -g ...` | headless process 直接輸出 `Debugger: Couldn't open socket`；本輪 shell session `66305` 已 Ctrl-C 停止，事後 `24764` 無 listener | `runtime_m2_4.py` 對已停止的 `24764` 收到 `ConnectionRefusedError [Errno 61]` |

第二輪同 port 的 GUI launch 曾因環境 escalation reviewer 的 transport failure 被
拒絕，沒有形成 process，未把它算成第三輪或 runtime evidence。兩輪實際 process
都已停止；沒有留下 mGBA child、listener 或 raw GDB session。

`runtime_m2_4.py` 的 diagnostic JSON 只寫 ignored `work/`：

```sh
PYTHONDONTWRITEBYTECODE=1 python3 games/summon-night-craft-sword-3/tools/runtime_m2_4.py \
  games/summon-night-craft-sword-3/roms/base/B3CJ-jp-from-zip.gba \
  --poc-rom games/summon-night-craft-sword-3/work/m2.3-poc.gba \
  --port 24764 --attempt 2 \
  --output games/summon-night-craft-sword-3/work/m2.4-runtime-diagnostic.json
```

輸出確認 `single_connection=true`、`packet_delay=0.08`、`retry_delay=0.25`、
transport provider 是 `core/gba/gdbstub_client.py`；兩次都在 connect 前拒絕，
所以沒有 `qSupported`、`?`、register、breakpoint 或 watchpoint hit。這是工具／
startup 的 blocked receipt，不是遊戲文字或 POC ROM 的 runtime 判定。

## 等價 static writer→destination 收斂

在沒有 live listener 的邊界內，`tools/runtime_m2_4.py` 先對 clean B3CJ ROM 做
`inspect_font.py` 的完整 static evidence，再檢查本機 writer function hash：

| caller → writer | local function SHA-256 | destination contract | 判定 |
| --- | --- | --- | --- |
| `sub_080036F8` → `sub_08002CB4` | caller `8593bbedfbfa610d0411f09ac808ccb4191ab7ff8b570f66168b94ddd639ee35`；writer `7ea0b0df799259d52eee5b818d7abcfa8fe51ddbdc0456fe202489769f67ee1b` | caller `r0` output buffer 傳為 writer `r1`；每 glyph `+0x80`；writer output span `0x80` | confirmed-static |
| `sub_0800379C` → `sub_080031E8` | caller `f79dcb74807def1c83fce4a737ea97847baee59dc033e37850800dbbca566a0e`；writer `f8c50f544edd95f65e987769c2add46ab779a02650a6220f43fc5bde17e69d9b` | caller `r0` output buffer 傳為 writer `r1`；每 glyph `+0x40`；writer output span `0x40` | confirmed-static |

兩條 callsite 都先經 `sub_0800348C` lookup；font loader 的 `gUnk_03002984`、
`glyph_id*0x18` 與 function/literal hash 仍由 M2.2 static inspector 驗證。這裡的
destination 是 RAM／output-buffer argument，不是 VRAM address；沒有把 `0x80` 或
`0x40` 誤稱為 tile stride，也沒有宣稱 palette、tilemap、OAM 或畫面可讀性。

同一個 diagnostic 重新檢查 ignored M2.3 POC 的 static changed／untouched proof：
adjacent untouched glyph `0x844` 位於 file `0x14e22e8`，changed `0x845`／`0x846`
位於 `0x14e2300`／`0x14e2318`，三者都是 12×12 rows／24-byte cells；changed
code units 仍 lookup 為 `0x845`／`0x846`。此為 static POC 的鄰接完整性證據，
不是 runtime render。

## coverage 與下一缺口

- **confirmed**：`gdb.port` launcher 參考路徑已嘗試兩輪；process ownership／停止
  邊界清楚；M2.3 POC static glyph mapping；兩條 writer→RAM output-buffer stride
  與本機 function hash；diagnostic 的 ACK／delay／一次 retry 設定。
- **provisional**：csm3 callsite 對 `r1` output buffer 的語意與 `0x80`／`0x40` writer
  span；它是 static callsite contract，尚未由 live arguments 觀察。
- **unknown／blocked**：自然 consumer reachability、controlled argument hijack、
  font loader live cache／RAM、lookup hit、writer live destination、VRAM／palette／
  tilemap／OAM、changed／untouched 畫面可讀性。

因此 M2.4 沒有解鎖 runtime gate，也沒有準備或提交 translation ledger candidate。
下一個最小缺口是取得能實際 bind `gdb.port` 且可完成單次 `qSupported` 的 mGBA
launcher；取得後才在已確認 consumer 上設 breakpoint/watchpoint，必要時另列
controlled argument hijack，並補 changed／untouched 的 live VRAM render。
