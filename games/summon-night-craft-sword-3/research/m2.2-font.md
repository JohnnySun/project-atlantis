# B3CJ M2.2 字型／glyph 鏈收據

固定輸入是日版 B3CJ `CRC32=12afae5d`、SHA-256
`39bc4cf448106aa4b8cdde235632ffb57432c4b1919c8843510b70b3787fad2d`，以及
csm3 commit `7e388ac861bbac289b1f86dc5b8fa46d47b1a1a2`。本切片只處理字型
定址、cell 格式與靜態 POC；不擴大 VM opcode corpus、不開始大批翻譯，也不
宣稱 ROM／BPS 回插或 runtime QA 已完成。

## 已確認的 renderer chain

| 層次 | 本機 B3CJ 證據 | 判定 |
| --- | --- | --- |
| `0x0308` consumer | csm3 `sub_0800D084` 位於 file `0x0d084`；本機同範圍 SHA-256 `4e6e33f072507741a23439defbe1c3ab64be1eafee8db055c94e7593b34fc40a`，並由 `sub_0800C38C` 接續文字處理 | confirmed，仍只把 0x0308 payload 當文字 record，不猜其他 control semantic |
| 一般 glyph renderer | csm3 `sub_08001F14` 的普通 u16 unit 呼叫 `sub_0800348C`，再按 parity 呼叫 `sub_08003BC0`／`sub_08003EB8`；本機 function-range hash 相符 | confirmed，output writer 的 ROM／RAM callsite 已對上 |
| UI text path | `sub_0800B730` 在本機 file `0x0b730` 呼叫 `sub_080036F8`；`sub_080036F8` 普通 unit 呼叫 lookup，再呼叫 `sub_08002CB4`，destination 每 glyph 增加 `0x80` | confirmed，`0x80` 是此 writer output buffer stride，不等同已取得的 VRAM tile stride |
| 次級 writer | csm3 `sub_0800379C` 呼叫 `sub_080031E8`，destination 每 glyph 增加 `0x40`；本機與 `sub_080036F8` 的 literal／function bytes 相符 | confirmed，實際用途與 runtime VRAM target 仍未升格 |
| font loader | `sub_08003620` 以 `(type=3, id=2)` 呼叫 `sub_08001D3C`，把 resource pointer 加 `0x1c` 寫入 `gUnk_03002984`；本機 file `0x3654/0x3658/0x365c/0x3660` literals 全部吻合 | confirmed，resource provenance 與 csm3 callsite 兩者獨立交叉 |
| code-unit lookup | `sub_0800348C` 本機 file `0x348c..0x350c` hash 相符；literal `0x08b6d624`、`0x08b704a4`、`0x08b6d5d0`、`0x03002984` 均相符 | confirmed，表位址、fallback 與 glyph-base formula 可重跑 |

`tools/inspect_font.py` 會在每次正式掃描先驗證上述固定 function ranges 與 literal pool；外部 csm3 名稱本身不會被當成本機證據。`sub_080036F8` 的 `0xc083` macro table、`0xf0ff` boundary 與 `gUnk_03005580` literal 也一併保留為 callsite evidence，但不在本切片命名新的 VM opcode 語意。

## Resource、cell 與定址公式

### BIT font resource

type-3 directory 位於 ROM file `0x14d446c`；csm3 `sub_08001D3C` 的 `id=2` entry 是：

| 欄位 | 值 |
| --- | ---: |
| relative units | `0x180` |
| span units | `0xc92` |
| payload file offset | `0x14d5c6c` |
| payload span | `0xc920` bytes |
| magic | `BIT\0` |
| header | version `0x08`、metric bytes `0c 00 0c 00` |
| glyph data bytes | `0xc900` |
| glyph base file offset | `0x14d5c88` (`payload + 0x1c`) |
| cell size／stride | `0x18` = 24 bytes |
| physical slots | `0x860` = 2144，IDs `0x000..0x85f` |
| resource tail | 4 bytes zero padding after the cell array |

每個 cell 是 12 rows × 2 bytes；每列的高 12 bits 以 MSB-first 表示 12×12
active bitmap，低 4 bits 是 padding。header 的 `0c 00 0c 00` 與 12×12
cell shape 一致，且本機多個已知字元的 cell bytes 可由 renderer 產生可辨識
的點陣。這確認了 cell width／height／row stride；palette 欄位、背景／前景
色值與 writer 寫入 VRAM 後的實際 tile arrangement 尚未由 live VRAM 證實。

### code unit → table entry → glyph cell

`sub_0800348C` 讀取 renderer 收到的 raw memory-order `[lead, trail]` 兩 bytes
（作為 little-endian u16），其有效表索引可寫成：

```text
if lead <= 0x9f:
    table_base = 0x08b6d624
    row = lead - 0x81
else:
    table_base = 0x08b704a4
    row = lead - 0xe0
column = trail - 0x40
index = row * 0xc0 + column
entry = table_base + index * 2       # u16, ROM address
table_value = *(u16 *)entry
if table_value == 0:
    return 0x08b6d5d0                 # fallback glyph record
glyph_id = table_value - 1
return gUnk_03002984 + glyph_id * 0x18
```

GBA address 與 ROM file offset 分開記錄：table A 是 GBA `0x08b6d624`／file
`0xb6d624`，table B 是 GBA `0x08b704a4`／file `0xb704a4`，fallback literal
是 GBA `0x08b6d5d0`／file `0xb6d5d0`。glyph cell 的靜態 file offset 則由
`0x14d5c88 + glyph_id * 0x18` 計算；`gUnk_03002984` 是執行時 RAM pointer，
不能把 `0x03002984` 直接當 ROM font address。

對固定 Shift-JIS code format 的嚴格掃描結果：

| 掃描項目 | 收據 |
| --- | ---: |
| formula pair candidates | 11280 |
| Python strict Shift-JIS accepted pairs | 6879 |
| format range 內被 strict decoder 拒絕 | 4401 |
| table value `0`，使用 fallback | 4789 |
| table value `1..0x860` 的 code units | 2087 |
| distinct physical slots 被使用 | 2087 |
| table target 超出本地 0x860 resource | 3 |

三個超出本地 resource 的 strict code unit 是 `ea a2`→`瑤`（table value
`0x1008`）、`ea a3`→`凜`（`0x4020`）、`ea a4`→`熙`（`0x2010`）。這裡只
記錄「strict Unicode identity」與「table target 不在本地 BIT resource」兩個
結果，不猜它們是否來自別的 resource、外部 glyph bank 或未載入資料。

## Unicode identity 與 addressing 分離的樣本

下表的 `identity` 只由 raw bytes 的 strict Shift-JIS decode 得到；`table`、
`value`、`glyph`、`cell` 則只由本機 B3CJ lookup table 與 BIT resource 得到。
兩組證據分開保存，沒有把 Unicode 字元名稱反推成 glyph slot：

| identity／raw Shift-JIS | table entry file | table value | glyph id | cell file |
| --- | ---: | ---: | ---: | ---: |
| `正` / `90 b3` | `0xb6ed8a` | `0x04d2` | `0x4d1` | `0x14dd020` |
| `直` / `92 bc` | `0xb6f09c` | `0x05c6` | `0x5c5` | `0x14de700` |
| `同` / `93 af` | `0xb6f202` | `0x062d` | `0x62c` | `0x14df0a8` |
| `部` / `95 94` | `0xb6f4cc` | `0x06d8` | `0x6d7` | `0x14e00b0` |
| `屋` / `89 ae` | `0xb6e300` | `0x01c4` | `0x1c3` | `0x14d86d0` |
| `ら` / `82 e7` | `0xb6d8f2` | `0x00cd` | `0x0cc` | `0x14d6fa8` |

361 筆 bounded source record 的 382 個 unique aligned double-byte units 全部
是本地 mapped glyph 或 fallback，沒有把上述三個 out-of-resource target 混入
現有 source corpus。這只表示目前這批 source 的 code units 可定址，不表示
全遊戲文字 coverage 完整。

## 實際可分配 slot 與靜態 POC

物理 slot 掃描得到：

| 類別 | 數量／範圍 | M2.2 判定 |
| --- | --- | --- |
| all-zero physical cells | 28，`0x000` 與 `0x845..0x85f` | `0x000` 已被現有 table mapping 使用；只有後者可列為未引用空白容量 |
| blank unreferenced slots | 27，`0x845..0x85f` | confirmed safe candidates，未改動既有 mapping |
| nonblank but unaddressable slots | 30，`0x141..0x15e` | 物理資料存在，不視為空槽，不分配 |

使用既有 repository 的 GNU Unifont 17.0.05（來源與授權見
[`font-sources.md`](font-sources.md)），`inspect_font.py` 產生一個 ignored
static POC：

| POC 項目 | 值 |
| --- | --- |
| custom raw code units | `ec48`→`的`、`ec49`→`你`；兩者原 table value 都是 `0x0000`，只作 opaque POC code unit |
| inserted slots | `0x845`、`0x846`；table values `0x0846`、`0x0847` |
| table entries | file `0xb716b4`、`0xb716b6` |
| changed cells | file `0x14e2300`、`0x14e2318` |
| adjacent untouched render | glyph `0x844`，cell file `0x14e22e8` |
| changed table/cell region | 52 bytes（4 table bytes + 48 cell bytes） |
| actual nonzero byte diff | 43（固定 Unifont source；cell padding／zero rows 不會重寫成非零） |
| patched ROM SHA-256 | `ccc447b5bd5453f5eb7d5d49d027f46fb18432815f7906c7781627dd7d16dc34` |
| static contact sheet SHA-256 | `dd9fa9b7c972e29d2950682fe9613867aefe2dc444686bca930343df86f901d4` |

POC 的 contact sheet 順序是 untouched `0x844`、changed `0x845`、changed
`0x846`；它只證明 table entry、24-byte cell packing 與 static renderer 可以
共同重建兩個 glyph，沒有更新 GBA header checksum、script resource、LZ77
container 或 runtime state。POC 不是翻譯，也不是可發布 patch；ROM、PGM、summary
JSON 皆在 ignored `work/`。

## 重跑方式與測試

```sh
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover \
  -s games/summon-night-craft-sword-3/tools -p 'test_*.py' -v

PYTHONDONTWRITEBYTECODE=1 python3 games/summon-night-craft-sword-3/tools/inspect_font.py \
  games/summon-night-craft-sword-3/roms/base/B3CJ-jp-from-zip.gba \
  --source-jsonl games/summon-night-craft-sword-3/research/summon-night-craft-sword-3-decoded.jsonl \
  --summary-output games/summon-night-craft-sword-3/work/m2.2-font-summary.json
```

工具每次都先驗證 B3CJ size／CRC32／SHA-1／SHA-256／header checksum，再驗證
csm3 function range hash 與 literal；若其中任一項不符便 fail closed。`source-jsonl`
只讀 `source_text` 計數，不把完整日文寫入 tracked output。

## Confirmed／unknown 與下一個最小切片

已 confirmed：`sub_0800D084` 到 renderer 的本機 callsite、type-3 font resource
provenance、12×12／24-byte cell、code unit→table→glyph address formula、8 個
addressing／identity 分離樣本、嚴格 code format 的 slot scan，以及不改既有 mapping
的 static POC。

仍 unknown／blocked：palette 與實際 VRAM tile layout、writer 的 runtime destination
與畫面可讀性、三個 out-of-resource table target 的來源、fallback glyph 的語意、
font resource／script container 的正式 encoder、ROM checksum／BPS rebuild，以及
RUNTIME-003 的 live VRAM 交叉驗證。M2.2 不因 static POC 把這些未知升格。

下一個最小安全條件是先建立 fail-closed 的 glyph allocation manifest／encoder：
只允許 `0x845..0x85f` 這批明確空槽、保留既有 codepage mapping、拒絕 fallback 與
out-of-resource target，並對 1–2 筆相同 byte length 的短 record 做 source hash、
font mapping、record／stream round-trip。runtime QA 仍可獨立等待 RUNTIME-003 解鎖；
在此條件前不開始大批劇情、支線、夥伴、鍛造、戰鬥或道具翻譯。
