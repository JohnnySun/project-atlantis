# M4.2：resource-16 short warning label

這是第三筆 cumulative static `ai_draft` target。它選用 resource 16 的一筆
opaque-free、10-byte／5-code-unit、單行 record；沒有專有名詞，不需要新增術語
或音譯決策。日文 source 只從 ignored 361-row table 讀取，本文件只保存 hash、
stable ID、結構與 target-side evidence。

## Ledger／translation contract

- `string_id`：`b3cj:t2:016:0x001e`
- source hash：`0c7840a194483b36af7414a8e8624c93d3a3ae62e6167eb1040daaae317e33d8`
- target locale：`zh-TW`；target：`警告！　　`；status：`ai_draft`
- target 是五個 code unit、10 bytes、單行；兩個全形空白是明確 text units，
  用來保留 record 長度，不把 `0x0000` terminator 當 padding。
- record controls 保留 `0x0308`／`0x0000`，following corpus opcode 只有
  `0x0308`，opaque control count 為零。
- ledger 由 `prepare → core restore → core strip` 產生；tracked ledger 只有
  source hash、target、context 與 review metadata，沒有 source text。

## Fail-closed selection／glyph contract

先對 resource 22 的下一個同長度候選做實際 cumulative probe；其輸出為
`500/496` bytes，因超過原 span 被 capacity guard 拒絕，沒有放寬 span 或做
pointer relocation。M4.2 改選 resource 16，壓縮後為 `180/192` bytes。

target Shift-JIS code units 固定為
`8c78 8d90 8149 8140 8140`。五個 unit 在 clean B3CJ font table 都已 mapped，
因此 `allocations=[]`，沒有觸碰 `0x845..0x85f` 的新槽，也沒有改動既有 glyph
table／cell。target-side glyph proof 的 glyph IDs 是 `0x2f1`、`0x373`、`0x009`、
`0x000`、`0x000`；mapping 與 cell hash 在 clean／target 相同。resource 16
相鄰 records `0x002c`、`0x004a` 以及 adjacent glyph `0x096` 仍 byte/render
identical。
