# M4.1：resource-22 wood-chopping rank label

這是第一個 M4 有界 zh-TW static batch。它只選一筆 resource 22 的短 label，
不含專有名詞或需要固定譯名的角色／地名；target 維持 `ai_draft`，runtime 與
人工審核仍 pending。原文只由 ignored source table 讀取，本文件只保存
`string_id`、hash、結構與 target-side 證據。

## Ledger／translation contract

- `string_id`：`b3cj:t2:022:0x004e`
- source hash：`956b323686afadc76cb837332e29e5a92db3d88a746c54f25a23d9a19b1d4f2c`
- target locale：`zh-TW`；target：`劈柴新手　　`；status：`ai_draft`
- target 是六個 code unit、12 bytes、單行；兩個全形空白是明確 text units，
  不是把 `0x0000` 當 padding。control shape 保留 `0x0308`／`0x0000`，後續
  corpus shape 為 `0x0003`、`0x0002`、下一個 `0x0308`，沒有 opaque control。
- ledger 由 `prepare → core restore → core strip` 產生，並通過 M3
  `validate_ledger.py` 的 source hash／stable ID／禁止 source 欄位檢查。

## Glyph／static insertion

- Existing mapped code units：`9056`（新）、`8ee8`（手）、`8140`（全形空白）。
- New opaque extension units：`ec67`→`0x84a`（劈）、`ec6c`→`0x84b`（柴）。
  兩者都在既有 fail-closed slot range `0x845..0x85f`，clean table value 是
  zero fallback，physical 24-byte cell 全零；未使用 `ec68`，因其 table target
  是 out-of-resource，維持拒絕。
- Glyph source 沿用 repository 已固定的 GNU Unifont 17.0.05 official
  `.hex.gz`，SHA-256 `2ae5311c8e123e9e85f5331cd012aa99757071df23243f1487fdbf8f3acd86be`，
  授權與來源見 `research/font-sources.md`。沒有新增未授權字型檔。
- adjacent untouched glyph `0x84c` 的 cell SHA-256
  `9d908ecfb6b256def8b49a7c504e6c889c4b0e41fe6ce3e01863dd7b61a20aa0`、static
  render SHA-256 `83c78b3fdc4cb9b2021552642f4a34d841b9c8e23ee7bfb7baef59082aea3759`
  在 clean／cumulative target 相同。

## Cumulative build／round-trip

`tools/build_m4_1_batch.py` 先從 clean B3CJ ROM 在記憶體重建 M2.5 target，再
套用 M4.1 font table/cell 與 resource-22 record；不會遺失既有
`b3cj:t2:024:0x0064`。最後重新檢查全部 361 筆：target `2`、untouched `359`；
M2.5 adjacent records 與 M4.1 resource-22 adjacent records 都 byte-identical。

resource 22 的 compressed size 是 `485 → 493` bytes，原 span `496` bytes，尚餘
3 bytes；因此這筆修改通過 capacity guard，沒有放寬變長／relocation 契約。
累積 target ROM SHA-256 為
`7ba9be55fed30a45b65f96c71e8b909337bdd039f04275e8d8c344aa81cfeec2`，CRC32
`4847fc57`；BPS 是 `2117` bytes、SHA-256
`a76b550d6893275b271239ed160c1e25191f655554d1acdc924bf42c7dfff9ab`，套用後與
target byte-identical。ROM、BPS、working source 與 summary 均在 ignored `work/`。

這是 static build／re-extraction／BPS evidence，不是 runtime 畫面或可發布 patch；
下一步是人工／字型 review、可達畫面 QA，及在 transport 解鎖後對 changed／adjacent
glyph 做 live renderer verification。
