# M5.5 後 clean 2350 受控 writer／VRAM QA

本收據只處理既有八筆 cumulative M5.5 target，不新增翻譯，也不把受控函式入口
冒充自然 `0x0308` consumer reachability。ROM、GDB memory、PPM 與完整 runtime
dump 均留在 ignored `work/` 或 `/private/tmp`；tracked report 只保留 hash、地址、
計數與證據邊界。

## Inputs and transport

固定 target 是 `b3cj:t2:024:0x0064`，target ROM 為 M5.5 applied output。正式
probe 先驗證：

- clean B3CJ：32 MiB、CRC32 `12afae5d`、SHA-256
  `39bc4cf448106aa4b8cdde235632ffb57432c4b1919c8843510b70b3787fad2d`
- M5.5 target：CRC32 `fc874c4d`、SHA-256
  `acfb3587a8217bf4ea444daf25f32c0947998a9203ee874db5006d7b6b016db6`
- BPS：4856 bytes、SHA-256
  `f0b030756e4744c5f5a42c8bb874341062c73df818ba86342e13a1cbe3c92b34`
- BPS apply：與 target byte-identical
- mGBA source：fixed HEAD `26b7884bc25a5933960f3cdcd98bac1ae14d42e2`
- clean SDL binary：compile-time GDB port `2350`、SHA-256
  `1ad2f1087941ea95ccc33d96b6ed45cff30da64f34c51f58b1f3e9dd7f4a6fe1`
- fresh own PID `91895`；啟動前後以 `lsof -nP -iTCP:2350 -sTCP:LISTEN` 核對
  `127.0.0.1:2350`，完成後只停止該 PID

正式命令（ROM、BPS、report 都不是 tracked output）：

```sh
SDL_VIDEODRIVER=dummy SDL_AUDIODRIVER=dummy \
  /private/tmp/atlantis-b3cj-mgba-2350-build/sdl/mgba -g \
  games/summon-night-craft-sword-3/work/m5.5-repeated-prize-header-applied.gba

PYTHONDONTWRITEBYTECODE=1 python3 \
  games/summon-night-craft-sword-3/tools/runtime_m5_writer_probe.py \
  games/summon-night-craft-sword-3/roms/base/B3CJ-jp-from-zip.gba \
  games/summon-night-craft-sword-3/work/m5.5-repeated-prize-header-applied.gba \
  --bps games/summon-night-craft-sword-3/work/m5.5-repeated-prize-header.bps \
  --bps-applied games/summon-night-craft-sword-3/work/m5.5-repeated-prize-header-applied.gba \
  --port 2350 --output /private/tmp/b3cj-m5.5-runtime-2350-probe.json
```

使用 `core/gba/gdbstub_client.py`，host `127.0.0.1`，timeout `8s`、packet delay
`0.12s`、retry delay `0.35s`；整個 probe 只有一條 GDB connection。qSupported
為：

```text
swbreak+;hwbreak+;qXfer:features:read+;qXfer:memory-map:read+;QStartNoAckMode+
```

初始 stop 是 `S02`。本輪曾有一次工具輸入 endian 被 fail-closed 拒絕：把
`ec64/ec65/ec66` 當成數值 halfword 再交換，lookup 未對齊；修正為現有 M5.5
payload 的 memory-order bytes `ec64 ec65 ec66 0000` 後，沒有沿用該負結果，另以
fresh PID 重跑成功。這也固定了工具不可對 codepage bytes 做第二次 little-endian
交換的測試契約。

## Observed natural anchor

自然 boot 執行先命中 `sub_08006BA4` 的 palette queue callsite，register contract
為：

```text
r0 = 0x03005d60
r1 = 0x05000000
r2 = 0x00000400
font pointer [0x03002984] = 0x094d5c88
```

這是自然 palette DMA queue anchor 與 runtime font-base readback；沒有宣稱自然
命中目標 resource 的 `sub_0800D084` consumer。

## Controlled writer and adjacent cell

在停止於自然 queue anchor 後，probe 對已確認的 `sub_080036F8` 入口做一次受控
argument setup，把 memory-order codepage bytes 放在本 session EWRAM scratch
`0x0203e000`，output 放在 `0x0203f000`，並以 `sub_08002CB4` breakpoint 觀察 lookup
結果。這是 controlled call，不是遊戲自然流程：

| code-unit label | observed glyph pointer | glyph id | output pointer | output non-zero / SHA-256 |
| --- | ---: | ---: | ---: | --- |
| `ec64` | `0x094e2330` | `0x847` | `0x0203f000` | `51` / `b2186d0ef43febba84caa7fedadd0ff2551b52beae89d9dc98020de17169f0bf` |
| `ec65` | `0x094e2348` | `0x848` | `0x0203f080` | `50` / `af3749bdb2fca8e41e9711dcc5e1b0411e697cfa25aaf6308f9a5a5604bc8093` |
| `ec66` | `0x094e2360` | `0x849` | `0x0203f100` | `30` / `895dc0baad6322b50b0a63235c47ed601a432a0700509f0df0dad52ea018aebc` |

Adjacent physical slot `0x846` was invoked separately through the glyph writer using
`0x094e2318`; its 0x80-byte output was all zero, SHA-256
`38723a2e5e8a17aa7950dc008209944e898f69a7bd10a23c839d341e935fd5ca`。這只證明
adjacent physical cell readback，不能代替自然相鄰 record 或 codepage consumer
驗證。

## Controlled queue, flush and display boundary

同一條 connection 接著受控呼叫：

```text
sub_08006BA4: source 0x0203f000 -> destination 0x06010000, length 0x180
DmaCopyMapAndPltt: 0x08006ac4 -> return sentinel 0x0800d084
```

讀回 text VRAM `0x06010000..0x180`：非零 131 bytes，SHA-256
`bad69ba786472e0f0e12fa7e1ec98e54ec010239f8fc335019a7ae6743f211c0`；三個 0x80
slice 的 SHA-256 與上表 writer output 一一相同。這是本作第一份由受控 lookup／
writer 到 queue／flush 再到 live VRAM 的連續證據。

同一 readback 的 palette `0x05000000..0x400` 非零 0、SHA-256
`5f70bf18a086007016e948b04aed3b82103a36bea41755b6cddfaf10ace3c6ef`；display
register 是 `DISPCNT=0x1040`、`BG0CNT..BG3CNT=0x0000`。以
`core/gba/render_vram.py --mode grid --columns 4` 對 ignored VRAM 產生的 32×24
PPM SHA-256 為
`71ef5ebe4c1fed34e36d5a27796f4f81d0a67ac04c82a3370d82f5c56f6c9c7d`，視覺結果為
全黑；沒有 palette／tilemap，因此不把它稱為可讀畫面。

| 項目 | 判定 |

| clean process、2350 listener、qSupported、single connection | `confirmed` |
| 自然 palette queue source/destination | `confirmed` |

| target `0x0308` consumer 的自然 reachability | `unknown` |
| target record 自然畫面、tilemap、palette usable、live OAM | `unknown`／未讀 |
| changed／adjacent 的自然畫面可讀性 | `unknown`；黑色 static render 不通過 |
| release patch | `blocked` |

`tools/runtime_m5_writer_probe.py` 將上述路徑固定成可重跑、fail-closed、只輸出
hash 的 probe；它不啟動 emulator、不重連、不把 controlled coverage 升格為自然
consumer，也不會變更八筆 `zh-TW`／`ai_draft` ledger。下一個最小缺口是自然
`0x0308`／UI reachability 加上 tilemap／palette／OAM 的畫面證據，或一份足以替代
它們的完整 static layout／release encoder；不新增 M5.6 或同型短句。
